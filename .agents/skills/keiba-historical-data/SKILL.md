# 史实赛马资料维护

以当前工作区的赛马项目为准。读取 `docs/historical-horse-maintenance.md`、本次涉及地区的单马文件、索引和测试；不要沿用对话中的旧总数或缓存赛事清单。结构和验证细节见 [项目结构与核对说明](references/project-contract.md)。

## 判断任务阶段

- “候选”“拟分”“先给我检查”：提供方案，保留用户逐轮修订后的最终中文名、基础分、最高分，不提前录入。
- “录入”“修正”“全面修订”：直接完成授权范围内修改与验证。已有确认可沿用，不重复请求批准。
- “检查并列出”：报告问题，不擅自修订。
- 用户明确校订的 CSV 或姓名列表优先于旧提案。先核对对应关系；不能凭行号匹配或覆盖未匹配的马。

## 新增史实马

1. 按原名、英文名、中文别名和 ID 查重。区分同名马、出生年份、所属地区；地区目录沿用项目归类，不能由出生国或一次海外胜利推断。
2. 拟分时选择当前库中同地区、距离、场地和成就相近的参照马，给出中文名、英文名、基础分、最高分及简短理由。用户已确认数值则直接使用。
3. 逐匹联网查胜利记录，优先 JRA、JBIS、NAR、HKJC、赛事主办方及官方赛果；可用其他赛马数据库交叉核对。明确年份、当时赛事名、名次、实际策骑人、距离、场地，保留支持这些事实的链接。资料有冲突就继续核查；未能确认的条目标为待核实。
4. 每次写入或修改胜鞍前，重新加载当前 `js/data/races` 可用列表。使用项目加载器取得真实注册结果，不能只检索静态 `id` 文本；部分赛事由程序生成。
5. 逐场核对赛事身份及实际骑手当年的有效生涯分段。默认缺比赛、缺骑手或年份不可用就跳过该条，记录原因。不得以主战骑手、通用骑手或相似赛事代替，不为通过校验擅自延长生涯。
6. 赛事更名或改程要有沿革证据，并检查当前规则如何使用距离、场地、年龄和性别限制。现有映射仅作线索，不是正确性证明。映射会制造错误参赛资格或适性时跳过并说明；是否扩展赛事库按用户授权处理。
7. 一匹马一个文件，用当前同地区格式注册；`races` 中新增胜鞍明确 `finish: 1`。只有资料可录而胜鞍全部不可用时，可以保留空数组，但明确说明该马尚无可用历史对手记录。
8. 在索引 `files` 末尾追加路径，保留已有顺序；同步 `js/data/changelog.js` 内容数量与 `tests/data-integrity.test.js` 预期数量，按实际加载结果计算。新增骑手同样同步计数。

## 能力平衡与姓名修订

- 基础分、最高分和逐场表现分是项目自定义数值，不等于现实官方评级。不得直接转换现实评分，或将骑手能力与马匹能力混用。
- 始终满足 `baseAbility <= ability <= peakAbility`，基础分不得高于最高分；本项目拟分沿用整数。
- 用户说“整体上调/下调 N 分”：提案阶段同步调整基础分和最高分；落库阶段还需检查比赛分，通常同幅平移以保留原有强弱关系，再逐场复核。只改基础分或最高分时，仅调整越界记录或用户要求重新评估的记录，不自动平移全部比赛。
- 重新拟比赛分时综合对手强度、胜差、当季表现、赛事地位与同库参照；普通胜利可处于基础分，代表性巅峰可接近最高分。不得机械地给所有 G1 最高分，也不必为了用满区间而虚构巅峰胜鞍。
- 姓名改动同步 `displayName` 与 `displayNameZh`；保留原文 `name`、正确英文名和稳定 ID。不要因中文名调整重命名 ID。
- 批量平衡先汇总指定地区/分数段及异常，保留修改前后差异。发现“基础分高于最高分”等无唯一解冲突时，继续处理独立条目并提出具体问题。
- CSV 工作按真实编码及表头解析，使用英文名/稳定 ID 对应并核查别名、重复和未匹配项。保留用户校对结果及原始编码，不能把乱码回写；用户要求同步时更新花名册，避免自动将旧花名册当作最新主库。

## 骑手补录

用户授权新增骑手时，核实日文正式汉字名、英文名、出道退役年份、年度成绩和代表性胜鞍，参考当前同地区骑手尺度拟分。按用户确认分段设置 `periods`，避免重叠；在 `affiliationMeta` 登记地区。实际运行结果在骑手对象的 `affiliations`，不要假设存在 `JockeyRegions`。普通补胜鞍不隐含批准新增骑手或改骑手能力。

## 验证与反馈

从项目根目录执行技能只读补充审计：

```powershell
node .agents/skills/keiba-historical-data/scripts/check-data.cjs .
```

数据实际修改后，依照项目维护约定运行 `npm test` 和 `npm run build:web`。只修改技能文档时无需构建应用；修改本技能脚本须实际运行。影响传奇候选资格或批量能力分布时按需运行 `npm run audit:legend`。

测试通过只能证明结构与约束，不能证明史实正确。线上胜场审计工具仅提供核查线索，不能代替逐场赛果证据。区分新增问题、原有问题和工具自身故障，不把未运行的验证写成通过。

最终反馈包括实际新增/修改数量、关键评分、未录入胜鞍（马名、年份、比赛、骑手、原因）、来源链接和测试结果。覆盖范围注明是全部胜场还是公开赛/重赏；不能遗漏低级胜场后宣称生涯胜鞍全部录入。已有授权只涉及本地维护时，完成本地结果即可，不自动提交、推送或部署。
