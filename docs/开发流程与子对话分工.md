# 开发流程与子对话分工

整理日期：2026-10-13。本文是协作约定，不授权具体业务修改；当前用户指令优先。

## 子对话划分

| 对话 | 负责 | 主要改动范围 |
| --- | --- | --- |
| A. 主线协调 | 拆分任务、审查与合并、更新日志、GitHub 同步与发布、维护本文和交接文档 | `docs/`、`js/data/changelog.js`、合并冲突 |
| B. 主席模式 | 现有主席模式的诊断与修复，含排赛、人口、繁殖、存档 | `js/rules/` 主席相关、`js/chairman-worker.js`、`js/chairman-storage.js`、对应测试 |
| C. 史实马数据 | 筛选、录入、胜鞍、中文名、CSV 校订 | `js/data/` 史实马文件与索引、`docs/historical-horse-roster.csv` |
| D. 界面与体验 | 首页、主题、各模式 UI、手机适配 | `index.html`、`css/`、`js/ui/`、`js/chairman-*-ui.js` |
| E. 血统与配种 | 有独立血统任务时开启，平时并入 B | 血统相关规则与数据 |
| F. 长测与审计 | 只读执行长期模拟和审计，整理结果 | 不改源码；输出写入 `artifacts/` 新子目录和结果文档 |
| 新模式 / 新功能 | 一项一个对话 | 由方案文档界定 |

- 新模式、或需要设计文档、改动三个以上文件、需要专项测试的新功能，开独立对话；小需求并入对应现有线。
- GitHub 同步和更新日志不单独开对话，由 A 负责（原因见“发布”）。
- 修改代码与执行长测分开：B 先逐项诊断并做最小修复，F 再按登记口径做小样本配对。

## 隔离

- 改代码的对话使用独立分支和 git worktree，例如 `feat/chairman-age-supply`、`data/historical-xxx`、`ui/home-mobile`、`mode/xxx`。只读诊断可在主目录进行。
- worktree 不含未跟踪的 `artifacts/`、`node_modules/`、`.cache/`：新 worktree 先 `npm ci`；历史证据用绝对路径读取主目录 `artifacts/`，不复制；新实验输出写入主目录 `artifacts/` 下按日期和任务命名的子目录。
- 共享文件归属：
  - `index.html` 脚本加载顺序：各线可能都要改，冲突由 A 合并时统一处理。
  - 史实马索引及测试计数预期：只由 C 修改。
  - `js/chairman-storage.js`（旧存档兼容）：只由 B 修改，其他线有需求提给 B。
  - `js/data/changelog.js` 及版本号：只由 A 修改。
  - `package.json` scripts：新增时在交接报告中说明。

## 单个子对话的流程

1. 开工：读 `CLAUDE.md`、`docs/claude-code-handoff.md`、本文及本线入口文档；检查 Git 状态。
2. 方案：涉及规则或数据口径时，先在 `docs/` 写方案或实验登记，写明假设和验收标准。
3. 实现：只改本线范围；超出范围的问题记录后交给 A。
4. 验证：开发中用 `npm run test:quick` 和本线专项命令；结束前运行 `npm test` 和 `npm run build:web`。界面改动另查桌面、手机宽度和控制台。
5. 交接报告给 A：改动文件、实际运行的命令与结果、未覆盖项、需要其他线配合的事项、一两句面向玩家的改动说明。实验类写明种子、世界组合、繁殖开关、年数、正式赛事分母。
6. 不提交到 main、不推送、不部署。

## 合并与发布（由 A 执行）

向 main 推送且改动命中 `index.html`、`css/**`、`assets/**`、`js/**`、`package.json`、`scripts/build-web.js`、`tests/**`、`.github/workflows/deploy-cos.yml` 时，`.github/workflows/deploy-cos.yml` 会测试、构建并同步到腾讯 COS。推送即发布，所以由 A 统一把关。

1. 逐个分支审查 diff 并合并到 main，每次合并后运行 `npm test` 和 `npm run build:web`。
2. 汇总本版改动写入 `js/data/changelog.js`（`meta`、`entries`，必要时 `contentStats`、`roadmap`）。版本号还出现在 `index.html` 的更新日志按钮 `aria-label` 和 `changelog.js` 脚本的 `?v=` 参数，以及 `tests/ui-workspace.test.js` 的断言中，需一起更新。
3. 更新日志与版本内容放在同一次或同一组提交中。
4. 向用户确认发布意图后才推送 `origin`（`Mika21p/HoseRacingSIM`）的 main。
5. 推送后检查 GitHub Actions 结果和线上页面。

只同步不发布时，推送功能分支，或只推送不命中上述路径的改动（如 `docs/`）。
