# 剧情模式现状盘点

整理日期：2026-10-13。分支 `feat/story-mode`（基于 main `97a7fa9`）。本文只记录现状，不改代码，也不代表设计意图已确定。后续方案见待写的 `docs/剧情模式完善方案.md`。

## 0. 结论摘要

- **定位**：剧情模式是“二岁前章 + 1998 经典三冠”的纵向切片。只有一个剧本 `jp-golden-road`、一个入口候选和一条路线；首页标注“未完成”，剧本菜单标注“剧情模式测试入口”。
- **流程骨架可以走完**：进入、相遇、命名、二岁自由赛历、朝日杯/电台杯二选一、三岁三冠、伤病与缺席、结局和年度总结都已实现。真实模拟器自动通关 400 局，未出现卡死或异常。
- **内容基本还是提要**：157 条文本中，101 条是 `outline`（方括号包着的“场景待后续细化”说明），2 条是 1999 年的 `placeholder`，54 条是 `final`，但 final 主要是选项文案、新闻、年代纪事和结局这几类模板句。玩家看到的对白、赛前背景、赛后场景、动态报道都还是一句话的提要，并标有“剧情提要 · 待优化”。
- **已确认的缺陷有 3 个**：京都新闻杯之后菊花赏无法报名；皋月赏输掉后赢下德比，仍会提示“三冠可能仍在延续”；生成场次被隐藏马击败时，优胜马会记成史实优胜马。另外有若干数据和口径问题，见第 4 节。
- **框架瓶颈**：通用规则里写死了大量剧本 ID 和年份；只有轮到对应决策节点时才能报名比赛，每条“热身赛 → 目标赛”路线都要手工配节点，容易出现死路；剧情没有通用的条件/变量机制，分支只能是“报名哪场、跳过、走哪条路线”；存档版本采用白名单，加载失败会直接删除存档。

## 1. 已实现的流程

### 1.1 进入

- 首页卡片：`js/data/home-modes.js:54-65`（`era`，徽章“未完成”，按钮“进入剧情模式”）。`js/ui/render.js:436` 渲染卡片，`js/ui/render.js:720` 输出 `#eraOverlay`。
- `js/app.js:313` 的 `openEra()` 会先静默保存正在进行的普通生涯，再切换到 `activeScreen = "era"`。启动时由 `js/app.js:2818` 调用 `loadEraGame()`。
- 加载顺序（`index.html:83-85, 107-108, 112`）：`era/registry.js` → `era/texts.js` → `era/golden-road-1998.js`（在 `historical-horses/index.js` 之后、所有 rules 之前）→ `rules/era-narrative.js` → `rules/era.js`（排在 `career.js`、`race-simulator.js`、`comments.js` 之后）→ `ui/era-render.js`。剧本在注册时只调用 `EraScenarioRegistry.register`；`validate()` 运行时才读取 `ns.Races`、`ns.HistoricalHorses`、`ns.Jockeys`，所以剧本文件放在 rules 之前没有问题。

### 1.2 开局设置

1. **剧本菜单**（`js/ui/era-render.js:121-163`）：填写“玩家称呼”（20 字，`era.js:23-25`），然后生成候选。
2. **候选生成**：`createEntrySetup()`（`era.js:349-360`）为 registry 中每个 `entryCandidate` 实体化一匹马（`materializeEntryCandidate`，`era.js:328-347`），外观、能力和练马师评语生成后冻结，并写入存档。**目前只有 1 个候选**。
3. **选择候选** → `selectEntryCandidate()`（`era.js:523-540`）→ `createRun({ onboarding: true })`。
4. **马房相遇**（5 个 `encounterNodes`，剧本 `golden-road-1998.js:94-111`）：到达 → 第一次对视（3 个即时反应，**不写入存档**，`era.js:1423-1449`）→ 练马师评估（6 项评语，准确度固定 `close`）→ 命名（30 字，`era.js:1451-1470`）→ 确认。
5. 玩家马模板（`golden-road-1998.js:54-75`）：1995 年生牡马，草地，适距 1800–3000m，核心距离 2400，实力 81–85 随机，普早型，巅峰期三岁春到三岁秋，练马师佐藤悠太（虚构），主战骑手高桥隼人（虚构，能力 70）。场地适性固定为 `{burst:○, sustained:○, attrition:△}`，毛色、体重、气性和重场表现随机（`era.js:248-289`）。

### 1.3 章节与事件推进

- **时间**：沿用生涯模式的半月回合（`TimeRules`，上旬/下旬）。可玩区间从 1997-06-01（二岁 6 月上旬）开始。`playableEnd`（1998-11-30）只在校验中使用，规则不会读取。
- **叙事队列**：`syncNarrative()`（`era.js:1252-1274`）每次调用都会重建 `pendingScenes`，场景来源有：
  - 相遇节点（`syncEncounterScene`）；
  - 故事队列 `pendingStories`/`storyHistory`（赛后场景、三冠提示、结局）；
  - 年代纪事（只归档，不打断流程）；
  - 比赛结果场景（`race-result:<eventId>`）；
  - 二岁舆论（11/16 一次性快照）；
  - 静态场景节点（23 个 `sceneNodes`，按日期和 `sceneNodeApplies` 条件出现）；
  - 赛前动态报道（三冠各一篇，在赛前一回合生成并冻结快照）；
  - 空闲时间场景（“推进到下一事件” / 强制休养）。
- 排序规则：先按回合，再按 `NARRATIVE_PRIORITY`（`era.js:757-765`），最后按序号。
- **推进**：`advanceNarrative()`（`era.js:1472-1485`）连续调用 `advanceTurn` 最多 48 回合，遇到新场景、比赛、结局或休养时停下。
- **章节标签**：`updateChapter()`（`era.js:1983-2012`），依次为 prologue → two-year-prologue → satsuki → derby → kikka → ending → summary。
- **二岁前章**：5 个自由赛历窗口（`golden-road-1998.js:188-217`），每个窗口“选一场或跳过”。参赛资格按新马 → 未胜利 → 500 万下/公开/G3 → G2 晋升（`era.js:570-599`）。8 月可以选择“等待出道”，11 月未出赛时可以“延期到三岁”。年末朝日杯（固定史实出走表）和电台杯（生成出走表）二选一，也可以都不参加（`routeGroup: "1997-year-end"`、`routes.twoYearFinal`）。12/21 的二岁总结之后进入 1998。
- **三岁**：每个经典赛前有“路线会议 → 确认报名 → 赛前背景（带叙事槽位）”节点。热身赛为弥生赏、青叶赏、神户新闻杯、京都新闻杯。另有 4 个氛围节点：1 月马房会议、玩家宣言、主战骑手印象、2 月世代版面会议，以及 7 月夏季马房。

### 1.4 比赛衔接

- 报名入口只有两个：决策场景的选项，以及赛程手册抽屉。两者都调用 `resolveSceneChoice(..., "schedule:<id>")`，并且**都要求当前场景是允许该赛事的 `race-decision`**（`era.js:1292, 1308`）。
- `buildRacePayload()`（`era.js:694-726`）：
  - `historical-fixed`：5 名史实对手（`opponentFromParticipation`），模拟器走传奇 6 头出走表路径（`race-simulator.js:1019, 1151`，`LEGEND_FIELD_SIZE = 5`）。对手直接使用固定的 `historicalScore`，不掷骰（`race-simulator.js` 的 `fixedHistoricalResult`）；同分时史实马胜出。
  - `generated`：`createGeneratedOpponent` 生成一匹“同世代备战对手”，模拟器再补隐藏的 `field-N` 对手。
- `completeRace()`（`era.js:2106-2203`）：如果比赛回合正处在伤病期或已被迫退役，就按缺席结算；否则锁定赛前状态，计算成长（`MaturityRules.evaluate`），运行 `RaceRules.simulateRace`，再用 `CareerRules.addRace` 写入生涯，最后按赛事类型结算（`settleKeyRace` / `settleImportantTwoYear` / 普通结果事件）。
- 越过关键赛日期还没出走时，`settleCrossedKeyRaces()`（`era.js:2082-2104`）按缺席结算，并记录史实优胜马。
- 取消报名（`era.js:1614-1665`）会重新打开原来的决策节点（`:retry:N`），并回退路线选择。

### 1.5 结局

- 只在菊花赏结算时（出走、缺席或伤病）触发，或在伤病被迫退役、玩家主动退役时触发（`era.js:2021-2062`）。
- 6 种结局（`endingTextIds`）。优先级：显式指定（injury/retired）> 有缺席（`absent`）> 三胜（`triple`）> 至少一胜（`partial`）> 无胜（`none`）。
- 两段式提交：`finalizeStage` 把状态置为 `ending-pending`，并把“赛季回顾 + 结局”加入故事队列；玩家读完结局场景后，`commitStageEnding` 才写入 `endingId` 和 `summary`，并显示年度总结（`era-render.js:460-477`）。
- 年度总结写死了“参赛关键战 x/3”和“1999古马战线尚未开放”。

| 项目 | 值 | 位置 |
| --- | --- | --- |
| localStorage key | `keiba-era-save-v1`（独立存档，不与其他模式共用） | `js/app.js:50` |
| 外层载荷版本 | `ERA_SAVE_VERSION = 3`，结构为 `{version, savedAt, entrySetup, run}` | `js/app.js:55, 1436-1455` |
| run 版本 | `RUN_VERSION = 5` | `js/rules/era.js:3` |
| 候选结构版本 | `ENTRY_SETUP_VERSION = 1` | `js/rules/era.js:4` |

- 保存时机：每次选择、命名、读报、取消或退役后调用 `saveEraGame()`；切换界面时静默保存（`app.js:270`）。
- 读档：`loadEraGame()`（`app.js:1405-1434`）。外层版本**必须严格等于 3**，然后执行 `normalizeEntrySetup` 和 `normalizeSave`。**任何异常都会 `removeItem` 删除存档**，界面只提示“剧情模式旧规则存档已清除”。
- `normalizeSave()`（`era.js:2369-2435`）接受 run 版本 `[1, 2, 3, 4, RUN_VERSION]`：
  - v1–v3：补齐字段，`twoYearProfile` 记为 `legacy_unrecorded`，由 `migrateLegacyEvents` 根据旧的 `keyRaceResults`、`career.races`、伤病和退役重建事件流，并移除普通新闻场景；
  - v1–v3 存档没有相遇流程，直接视为已完成相遇；
  - v4：`migrateV4Calendar` 根据已出走或已报名的赛事反推窗口选择，过期窗口记为 `migrated-expired`，旧节点归档，按需补冻结二岁舆论；
  - 版本低于 5 时，用 `migratePast` 重建叙事，把已过去的场景归档而不是重新播放。
- 现有测试覆盖了 v1、v2、v4 → v5 的迁移（见第 5 节）。

## 2. 剧本数据结构

### 2.1 registry 字段约定（`js/data/era/registry.js`，以 golden-road 为样本）

`validate()` 检查日期格式、赛事/马/骑手引用、固定出走表人数和 `historicalScore`、文本 ID 是否存在、可触发文本不能是 placeholder、报道和舆论必须是 outline、日历窗口与赛事的双向链接、场景类型和发言人。当前校验结果为 0 条警告。

### 2.2 文本 ID 机制（`js/data/era/texts.js`）

- ID 规则：`<textNamespace>.<年份>.<主题>.<变体>`，例如 `jp.golden-road.main.1998.derby.post.win`。registry 用“字符串里含 `.`”来识别文本 ID（`registry.js:28-41`）。
- 状态：`placeholder`（禁止显示，`resolve` 会抛错；`queueStory` 遇到时退回 fallback）、`outline`（必须是一对方括号包着的一句话）、`draft`（已定义但未使用）、`final`。
- 令牌：17 个注册令牌（`texts.js:4-22`），一次性替换，玩家输入不会被二次解析；出现未注册令牌时校验报错。
- 叙事槽位：base / history-context / speaker-reaction / worldline / future-hook。场景节点设 `useNarrativeSlots` 后，由 `EraNarrative.selectTextSlots` 按事件流画像选择，并在场景生成时冻结快照。

## 4. 完整度与缺陷

### 4.1 完整、可玩

- 候选冻结、相遇、命名、自由赛历资格、年末二选一、取消后重开节点、赛前报道快照、二岁舆论快照、缺席与伤病结算、6 种结局两段提交、报纸箱、v1–v4 迁移，都有实现和测试。
- 自动通关（真实模拟器，**未固定随机种子**，每种策略 200 局）：两种策略都没有出现卡死、`ignored` 或异常。

## 6. 框架瓶颈

1. **通用规则写死了剧本内容**。只有一个剧本时可以运行，但无法加第二个剧本，也无法把 1999 年接上：
   - `era.js`：205（fallback 文本 ID）、565（1997 年）、896-897（朝日杯/电台杯 ID）、1199/1227/1240（1998 文本 ID）、1553、1639-1641（年末路线）、1799-1801、1964（三冠提示）、2001（1998 年）、2056（菊花赏 ID），以及 `chapterId === "kikka"` 被当作阶段终点（1798、2089、2132、2198）；
   - `era-narrative.js`：65、99、105-108（1997/1998 和 `1998-04-19`）、134、140-141、196-198（三冠 ID）；
   - `era-render.js`：466-476（“x/3”、1999 文案）；
   - `eventIndex`（`era.js:966`）在事件缺少 scenarioId 时回退到默认剧本。
2. **报名依赖当前决策节点**。抽屉也受当前场景约束，所以每条“热身赛 → 目标赛”路线都要手工配节点日期，漏配一个就是死路（D1）。没有“目标赛自动开放确认”的通用机制。
3. **阶段与结局模型固定为“三冠”**：`keyRace` 加 `classicWins === 3`，结局只在菊花赏触发，`tripleCrownPossible` 是全局字段。要做古马路线、牝马路线或多阶段剧本，需要把“阶段/目标/结局条件”数据化。
4. **剧情表达能力有限**：
   - 条件字段只有十个固定谓词（`sceneNodeApplies`）；
   - 没有通用旗标、变量或好感；
   - 对白选择只有“即时反应且不入档”这一种；
   - 场景槽位固定 5 个；
   - 文本集中在一个 `texts.js` 里，没有按章节拆分；
   - 文本状态里的 `draft` 没有使用。
5. **对手与内容来源**：热身赛和二岁赛事全部使用生成对手，史实对手只出现在 4 场固定出走表里，资料只有名字；固定出走表由人工维护能力分和骑手能力，没有与资料库联动（4.3 的冲突就是这样来的）。
6. **存档脆弱**：
   - `normalizeSave` 用版本白名单 `[1,2,3,4,RUN_VERSION]`。升到 6 时如果忘记把 5 加进白名单，v5 存档会被拒绝；
   - 外层 `ERA_SAVE_VERSION` 严格相等；
   - 加载失败直接删除存档；
   - 每个版本都要累积手写迁移函数；
   - 只有一个存档槽位。
7. **性能与可测性**：`getCurrentScene` 每次都会完整调用 `syncNarrative`，`getScheduleOptions` 会对 31 场赛事逐一计算预览和可报名计划。目前规模没有问题（400 局自动通关约 13 秒），但每加一层内容都会线性增加。随机数没有剧情专用种子，平衡回归无法复现。

## 7. 待讨论的问题（供第二阶段方案参考）

- 剧情模式的玩法定位：“史实纵向切片 + 改写世界线”继续深化，还是扩展为多年份、多路线？是否保留 1999 古马篇？
- 是否允许缺席后进入 `partial`，结局是否需要更多组合？
- 朝日杯适距外“陪跑”是有意设计还是需要调整？经典赛约 22% 的胜率是否合适？
- 热身赛是否引入史实对手。引入的话，需要把 `eraHorses` 中的 10 匹（以及弥生赏、京都新闻杯等热身赛的史实出走马）交给 C 线录入。
