# 主席模式试玩反馈修正验收

日期：2026-09-21。已完成本地实现与生产构建，未发布线上。

## 交付行为

### 游戏、备份与恢复点

- 入口统一为“游戏管理”：每局只列一份当前进度，支持继续、改名、删除。
- 设置内“备份与恢复”管理10个独立手动备份和自动恢复点；游戏管理也可以直接打开手动备份，来源游戏被删除后仍能恢复。
- “恢复原游戏”默认覆盖该游戏当前进度，并先保存“恢复手动备份前”回退点；“作为新游戏”明确创建独立副本。来源游戏已删除时，恢复为新游戏。
- 游戏删除同时清理其实体、历史、恢复点与事务日志，保留手动备份；备份删除只清理该槽快照及目录。
- 删除与恢复执行前显示对象和影响。世界编辑权、进度版本和备份时间戳再次校验；事务失败不留下半份数据，不影响其他游戏。

### 所有评分使用整数

- TF单场、年度TF、WTR赛事分、年度覆盖、基准和推荐分统一为整数。着差换算、基准评估、平均数等计算过程保留精度，最终输出才取整，不改比赛得分、名次、着差和奖金。
- 统一四舍五入，负数半值远离零：120.5→121，−1.5→−2；不会输出负零。
- 人工输入及草稿写入拒绝小数。空分与0分独立；推荐草稿不会自动成为核准评分。人工基准固定原值，其余马按完整公式推算后取整。
- 旧档增加 `ratingPrecisionVersion=1`。首次以可写方式读取时建立“整数评分转换前”完整快照，再一次事务转换成绩、年度档案、草稿、基准、前走缓存和相关公开摘要。
- 转换后重新汇总已核准赛事WTR，年度人工覆盖仍优先；历史比赛事实、获奖结果、冻结选票及修订原始证据不改写。旧证据的界面评分按整数显示，原小数仍可在转换前恢复快照中追溯。
- 数据库v6和完整格式v5保持不变；新精度存档含小数权威评分会拒绝导入，旧精度存档允许通过受控转换读取。

### 当前年龄创建赛马

- 自建表单用“当前年龄”，默认2岁；按当前游戏年反推内部出生年份，成长状态初始化到当前半月，无虚构赛绩。
- 已出赛或有子代的自建马不能改年龄。亲本性别、年代和关系仍按既有规则校验。
- CSV新增可选“导入时年龄”。只填年龄时按导入当年生成；同时填出生年份时必须一致。旧模板继续有效。
- 创作导出保留出生年份，年龄列留空，防止同一文件在不同年份导入时出现两个互相冲突的时间依据；导入预览显示实际年龄。

### 前走参考

- 评分表展示“前走成绩／WTR”，展开可见日期、格付、场地、距离、TF和着差。
- 按出赛时间严格早于本场的最近一次记录定位，首次出赛单独标注。退赛是一次出赛，不跳过；后台OP、隐藏比赛同样参与。
- 前走WTR读取该场最新核准分，不使用年度WTR，也不冻结为本场结算时的旧缓存。0显示0；无评分显示“未核准”。
- 先按稳定前走记录编号查询；旧数据或编号无效时使用马匹＋时间索引回查，不能返回本场或未来比赛。
- 前走重赏可进入评分窗口，OP保持后台赛事的简要展示约束；跳转、返回、关闭、刷新后草稿均保留。

## 验证结果

| 项目 | 结果 |
| --- | --- |
| 常规回归 | 169项通过，0失败 |
| 新增专项 | 6项规则／存储／CSV测试，加1项实际界面交互测试 |
| 五年运行 | 完成10,404次出赛，未发现重复结算；末年335匹现役 |
| 大型历史 | 1000匹现役、20年、51,840条成绩；保存、查询、恢复、导出通过 |
| 大型历史参考耗时 | 测试环境保存约19.2秒，最新50条查询16毫秒，导出14.8MiB；不是所有设备的速度承诺 |
| 浏览器 | Chrome 1440×900桌面、390×844手机，无脚本错误与页面横向溢出；手机评分保存按钮在视口内 |
| 评分往返 | 前走WTR为0正确显示；马匹／前走比赛跳转及刷新后草稿130保留并核准 |
| 游戏管理 | 按原身份恢复备份后仍只有1局；删除来源游戏后备份可恢复；删除备份后游戏仍保留 |
| 自建赛马 | 手机创建当前4岁马，刷新／恢复后仍为4岁；出生年份不再作为表单输入 |
| 构建 | `npm run build:web`通过，已更新相关脚本缓存版本 |

自动化覆盖整数边界、人工覆盖、迁移失败回滚、迁移重复读取与恢复重放、前走补分／退赛／跨时间排除、来源游戏恢复失败、删除事务失败、另一页面编辑权冲突及CSV年龄冲突。

测试与截图在 `artifacts/feedback-*`；可重复浏览器脚本为 `scripts/check-chairman-feedback-browser.js`，使用独立浏览器上下文，不接触玩家本地存档。
