## 4. 全项目开发边界

- 普通生涯、传奇、肉鸽、剧情、主席均属于移交范围；血统、适性、史实库、殿堂、构建和发布是跨模式基础设施，不是可以忽略的附件。
- 用户已确认的马名、数值、剧情正文及业务规则优先保留。新的史实事实需联网核实，不以测试通过替代事实核对。
- 主席存储/Worker 改动须考虑旧档、随机状态、主线程与后台结果一致；剧情原型存档规则另看 `era-save.js`，不将某模式策略扩展为全局策略。
- 剧情方向是 1996–2000 日本黄金时代、单马重玩、历史世界 + 动态叙事，只有玩家参赛比赛结果改写。当前落地与审核集中在 1998–1999，不表示五年内容全部完成。首页旧 1997–1998 文案也不是现行设计范围依据。
- 新增赛事还要核对史实胜鞍马覆盖、实际骑手匹配及有效年份，不能只检查 raceId 唯一。
- 史实库任务先读 [技能原文](../.agents/skills/keiba-historical-data/SKILL.md)、[项目契约](../.agents/skills/keiba-historical-data/references/project-contract.md)、[维护说明](historical-horse-maintenance.md)。一匹马一文件、稳定 ID、索引追加、实际统计与测试同步。
- `js/data/changelog.js` 是面向玩家的功能与玩法记录，不写内部验收/重构过程；本轮不改日志或版本号。

## 5. 怎么实际完成交付

### 同机、同工作区接手

旧写入者停止后，新 agent 可以先在本剧情工作区只读接手。这能看到未提交成果，但**工作区中存在文件不等于已备份**。新 agent 先提交接手报告，不能立即同步 main 或清理未跟踪文件。

### 换机器或另建干净目录

1. 用户先决定交付版本与是否授权检查点提交/备份。这次尚未授权，因此未执行。
2. 筛选应保留的已跟踪修改、未跟踪源码/测试/文档、预览配置；不要 `git add .` 无差别纳入本机设置与原始实验大文件。
3. 如获授权，可在功能分支固化检查点；不自动推送。换机器需要用户选定 Git 传输或受控文件备份方式。仅导出补丁不包含未跟踪文件；仅复制 worktree 文件夹中的 `.git` 指针也不是独立仓库备份。
4. 单独清点与备份主目录 `artifacts/` 等原始证据，保留来源、种子和场景。旧文档的约 1.43 GB 只是历史体积，本轮未重算。
5. 浏览器存档另行备份/导出并验证恢复；不同浏览器、profile、端口和主机名的存储不会随源码迁移。不得通过清空站点数据“修复”移交。
6. 新环境 Node >=20，执行 `npm ci`，新克隆执行 `npm run hooks:install`；不要携带密钥、账号权限或本机绝对 hooksPath 配置。

### 后续整合主线与剧情（未执行、需单独授权）

- 先保存两侧成果并明确要在哪个分支整合，再处理 main 更新与剧情修改；不能覆盖复制整目录。
- 高风险共享点：`index.html` 加载顺序/版本参数、`package.json` 测试列表、`tests/ui-workspace.test.js`、史实马索引及计数、首页 UI、主席 Worker 与规则、测试 fixtures。
- app 创建的 worktree 若要同步基线，遵循当前客户端的基线同步工具约定；工具不支持的 checkout 才采用常规 Git 流程。无论方式如何都先保护未提交改动，不在本轮自行操作。
- 合并后须重新建立游戏测试、构建和浏览器基线。任何一侧历史测试通过都不能证明整合版本通过。
