# 主席模式 NPC 排赛：阶段 0 准备与基线

日期：2026-09-28

状态：本文为阶段 0 完成时的历史记录。阶段 1 已完成，见 [阶段 1 实现与验收](主席模式NPC排赛阶段1实现与验收-2026-09-28.md)。

后续发现本阶段工具漏记创建时的初次规划诊断，因此部分规划累计计数不完整；原世界结果未受影响。修正后的修改前／修改后正式对照和源码依据详见阶段 1 报告，不混用本文旧计数。

对应 [分阶段开发与验收规划](主席模式NPC排赛优化分阶段开发与验收规划-2026-09-28.md) 的阶段 0。本阶段建立观察与复现能力，不调整排赛权重、赛事声望、远征规则、默认人口或比赛算法。

## 1. 本阶段交付

- 在新版排赛函数中增加默认关闭的诊断回调。回调接收独立副本，数据只交给离线审计工具，不写入普通世界存档。
- 固化 6 个可复现小场景：冷门赛事吸走强马、跨距离合并、海外空场吸引、前哨与目标间隔冲突、没有出赛时的海外驻留、奖金变化对照。
- 增加离线审计入口，记录候选筛选、公开评分、基础效用、缺人奖励、容量、补位及合并前后变化。
- 分开记录年龄、性别、资格、伤病休养、出赛间隔、运输、系列冲突、已有锁定承诺及赛事设置排除。
- 记录源码清单和指纹、Git 基准提交、运行环境、实际人口与年度目标、生成设置和规则版本。
- 保存初始世界与逐回合检查点；支持预算停止后恢复，拒绝用不同源码或配置继续同一条记录。
- 将取消场次和首年纳入统计，并按地区、级别、草泥地、距离、年龄及性别限制统计细分缺口。

## 4. 指标解释与使用限制

- “缺人奖励改变选择”指分配时选中的候选，其基础效用低于当时仍有容量的最高基础效用候选；不是根据最终人数事后猜测。
- 补位和合并次数按每次规划中每匹马的调动累计。同一匹马可在不同回合重复计数，不等同于实际出赛次数。
- “目标不同”可能包含合法前哨，不能直接当成错误；另记不同赛事且日期差不足三回合的目标间隔冲突，作为需要检查的信号，不作为引擎硬约束违规。
- 改签率分母仅包括具有有效旧报名、且本轮允许重新规划的机会；首次报名、正常完赛后清空、锁定保护不计入。
- 海外出赛以当时归属地区为参照；跨交通组出赛、地点变化、跨组移动、返乡和驻留分别统计。
- 驻留按回合开始时的实际地点采样，包含没有比赛的回合；试验结束时尚未结束的驻留属于截尾观察，不推断其最终总长度。
- 取消／小场原因采用“资格池 → 可达且未被承诺阻挡的候选 → 最终分配”的观察顺序。主因分为资格池不足、休养／运输／承诺限制、分配／赛程冲突，并附各项证据。这不是反事实因果证明，不假装能精确回答某个限制取消后的全部结果。
- 未胜利／条件等按需补充赛不进入命名赛事开赛率分母；小场和取消命名赛事保留在分母。
- 当前没有声望数据，所以报告只能给出 G1 指标，不能冒称“高声望 G1”指标。
- 统计是本次两个首年的基线观察，不是默认人口经过校准的证明，也不是跨种子或长期稳定性结论。

## 5. 复现入口

先从项目根目录执行。输出路径示例使用新名字；为保护已有记录，非恢复模式不会覆盖已有输出。

```powershell
# 六个小场景；默认命令仅运行场景，不会启动多年模拟
npm run audit:chairman:scheduling -- --scenario=fixtures --out=artifacts/scheduling-fixtures-new.json

# 日本默认规模，一个完整首年；每次交易都检查审计开关一致性
npm run audit:chairman:scheduling -- --scenario=japan --seed=123 --years=1 --out=artifacts/scheduling-japan-new.json

# 全地区组合首年
npm run audit:chairman:scheduling -- --scenario=combined --seed=123 --years=1 --out=artifacts/scheduling-combined-new.json

# 限定本次执行最多推进两个半月回合，保存检查点
npm run audit:chairman:scheduling -- --scenario=japan --seed=123 --years=1 --max-turns=2 --out=artifacts/scheduling-resume-new.json

# 同一份源码和配置下继续；仍可指定新的本次回合预算
npm run audit:chairman:scheduling -- --scenario=japan --seed=123 --years=1 --resume --out=artifacts/scheduling-resume-new.json

# 审计专项回归
npm run test:chairman:scheduling
```

每个完整赛季报告旁另有 `.initial.json.gz` 初始世界和 `.checkpoint.json.gz` 检查点。恢复需保持同一运行环境才能继续比较性能；源码、工具或配置变更后使用新输出建立新基线。

`status: complete` 只表示指定模拟运行完成，不代表排赛质量或阶段 4 人口指标通过。`stopped-at-turn-budget` 明确表示本次预算停止，部分年度不冒充完整年度。

## 6. 检查范围

- 审计专项共 7 项，已纳入常规检查：六场景开关一致、回调副本隔离、候选排除原因、完整小世界赛季及繁殖年末一致、取消分母、赛事设置排除、检查点恢复和指纹拒绝。
- `npm run test:quick`：336 项通过，0 失败，约 47.6 秒。
- `npm run build:web`：成功生成本地生产构建。
- `git diff --check`：通过；只有工作区换行风格提示，无差异格式错误。
- 日本和全地区各 24 次半月推进＋1 次年末结算，共 50 次完整交易开关对照全部一致。
- 另将 5 个有完整世界输出的小场景与 Git HEAD 中未添加诊断回调的排赛实现比较，输出世界摘要全部相同。奖金场景另以固定输入的报名变化对照记录。
- 逐回合停止／恢复与直接连续执行的世界摘要、统计明细一致；修改检查点源码指纹后，工具拒绝恢复。

常规回归和生产构建在两组性能测量完成后执行，不与本轮性能采样争用计算资源。

诊断回调关闭时不生成诊断明细、不添加存档字段。详细排赛审计具有明显额外开销，普通玩家推进流程不会打开该回调。

本阶段没有执行浏览器交互测试，也没有启动 10～20 年人口校准。离线时间和进程内存不能替代浏览器端等待时间、保存性能或完整历史存储体积。

## 7. 下一阶段的输入

- 将跨距离合并和补位推翻目标作为阶段 1 的明确修正场景。
- 保留本报告的人口和种子不变，先比较算法行为；不要先增加人口以掩盖异常。
- 声望及完整目标／远征生命周期仍按规划阶段 2、3 实施，本阶段没有提前引入。
- 长测前先用少量种子和回合筛选；详细诊断与逐交易双跑适合基线和问题复现，不能把其耗时当作普通模拟吞吐量。
- 后续若需要大量人口参数搜索，应在确保口径一致的前提下提供轻量统计模式，并抽样进行完整一致性复核；当前工具没有关闭逐交易校验的隐式开关。
- 各阶段正式阈值须在使用相应指标调参之前登记。95% 开赛率等仍是规划中的建议，不因本轮两条基线表现好就宣称已完成总体定标。
