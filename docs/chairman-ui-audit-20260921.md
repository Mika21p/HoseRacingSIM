# 主席模式 UI 体验分析报告

检查日期：2026-09-21。对象为当前本地工作区及 `http://127.0.0.1:8765/`，不代表远端部署版本。本轮只检查并出具报告，未修改产品代码，未操作用户真实存档。

结论：需要先修复交互中的定位与状态保持，再整理信息层级。暮色配色已基本统一；主要问题是浮层越界、重绘导致的筛选/导航状态丢失，以及功能增长后缺少明确操作分组。并非所有展开收起都有异常。

## 检查范围与方法

- 使用独立浏览器上下文和隔离测试存档，实际操作九个一级页面：概览、赛历与马场、马匹、结果与评分、年度奖项、榜单、繁殖、殿堂、设置。
- 1440、1024、768、390、320 px，共 45 个主要页面/屏宽组合；另检查筛选、多选、列表展开、马匹弹窗、评分、系列赛、评议会和存档页面。
- 使用固定种子、160 匹马的测试世界。赛果检查存档推进九个半月，并将普通赛调整为 G3，以确保评分界面有充分的记录；另用未调整赛历的世界检查筛选、繁殖和自建马详情。此处只评审界面，不据此判断游戏平衡。
- 对比截图、控件边界、滚动位置、焦点与前端代码。主要检查中没有页面脚本报错，没有发现整页横向溢出；这不意味着内部菜单没有被裁切。
- 没有重跑完整规则测试，也未遍历所有年末状态、导入文件组合和多年超大存档。

## 已复现的交互问题

### 1. P1：马匹详情的“更多”菜单被裁切，操作文字与点击区域不完整

复现：马匹列表 → 点马名 → 概况 → 上方“更多”。

390 px 手机中，菜单宽 160 px，但左边界为 **-101 px**，只有右端约 59 px 落在屏幕内；“导出家族模板包”大部分不可见。1440 px 桌面也出现相同性质的问题：菜单左边界约 40 px，而弹窗从 120 px 开始，左半段被弹窗内容区裁切。

原因：所有 `.cm-menu` 都相对按钮固定 `right: 0`，缺少边缘碰撞检测；`.cm-dialog-content` 的滚动裁切进一步遮住越界部分。列表右侧的菜单通常没有同样严重的问题，不能按同一种定位覆盖所有场景。

建议：按可用空间向左/右、上/下展开，并限制在当前弹窗或视口内；手机优先使用固定底部操作面板。保持 Escape 关闭和焦点返回。

证据：[手机菜单截图](../artifacts/chairman-ui-audit-20260921/horse-menu-mobile.png)、[桌面菜单截图](../artifacts/chairman-ui-audit-20260921/horse-menu-desktop.png)。代码位置：`css/chairman.css:116`、`:145`、`:149`，`js/chairman-ui.js:5`。

### 2. P2：手机选择一个筛选条件后，筛选区突然收起，列表跳位

复现：手机马匹列表 → 筛选 → 地区 → 勾选一个地区。

筛选按钮从展开变回收起，焦点落到 body；列表首行从 **y=523.6 px 跳到 y=315 px**，上移约 **209 px**。想再选择第二个地区，需要重新展开筛选和地区菜单。桌面多选菜单也会在每次选中后关闭。

原因：常用筛选每次 change 直接提交并重建页面；`.cm-filters-open`、多选菜单展开状态和当前焦点没有恢复。保存了“更多筛选”的展开偏好，但没有保存外层手机筛选状态。

建议：保持面板和多选菜单打开；连续选择结束后统一应用，或局部更新列表而不重建筛选区域。更新后保留操作控件位置与焦点。

证据：[展开前后记录](../artifacts/chairman-ui-audit-20260921/extra.json)、[筛选展开](../artifacts/chairman-ui-audit-20260921/mobile-filter-open.png)、[选择后](../artifacts/chairman-ui-audit-20260921/mobile-filter-selected.png)。代码位置：`js/chairman-ui.js:21`、`:32`、`:53`，`js/chairman-office-ui.js:194`。

### 3. P2：高级筛选尚未应用的选择会被其他操作静默撤销

复现：桌面马匹列表 → 更多筛选 → 性别选择“牡马”，暂不点应用 → 修改地区。

性别从“牡马”恢复为空。界面没有明确提示它是未提交草稿，也没有提示修改地区会撤销它。

原因：常用条件即时生效，高级条件等待“应用”；`primarySubmit()` 调用 `restoreAdvanced()`，明确恢复高级筛选原值。这是现有交互规则造成的误解，并非已保存游戏数据丢失。

建议：统一提交规则。较稳妥的是所有筛选先编辑、统一应用/重置；如保留即时筛选，应保留高级草稿，并清楚标出“待应用”，不能悄悄清空。

证据：`audit.json` 中 `advancedBefore=["牡马"]`、`advancedAfter=[]`。代码位置：`js/chairman-ui.js:20`、`:21`。

### 4. P2：切换后当前导航项跑出视野，一级和二级标签都存在

复现：390 px 手机横向滑动主导航，点击“设置”。页面确实切换，但导航重置到最左侧；“设置”按钮位于 **x=602～658 px**，完全不在 390 px 视口内。年度奖项、榜单、繁殖、殿堂也受影响。

繁殖页面的二级标签相同：点击“繁殖榜单”后，选中项位于 **x=411～489 px**，标签容器宽 316 px，滚动位置又变为 0。

原因：重建导航节点后未恢复横向滚动，也未将当前项滚入可见区。

建议：短期保留导航滚动位置，并确保活动项可见；中期把手机九个横向入口改为有清晰分组的导航面板，页面标题始终明确显示当前位置。

证据：[设置页截图](../artifacts/chairman-ui-audit-20260921/settings-390.png)、[繁殖榜单截图](../artifacts/chairman-ui-audit-20260921/breeding-boards-mobile.png)。代码位置：`js/chairman-app.js:107`，`js/chairman-breeding-ui.js:23`。

### 5. P2：弹窗内部展开内容会推动整个弹窗上下移动

复现：桌面自建马详情 → 展开/收起“自建参数”。

1440×900 下，折叠时弹窗顶部 **y=183.4 px**、高度 533.1 px；展开后顶部变为 **y=36 px**、高度 828 px；收起后又回到原位置。标题、关闭按钮和阅读起点往返移动约 **147 px**。

原因：弹窗只限制最大高度，实际高度随内容变化，并保持垂直居中。属于可复现的布局重定位，不是随机渲染故障。

建议：详情工作区使用稳定高度或固定顶部位置，展开只改变内容区滚动高度。小型确认框可以继续自动高度居中。

证据：[展开截图](../artifacts/chairman-ui-audit-20260921/custom-parameters-expanded.png)、`extra.json` 中三次弹窗边界。代码位置：`css/chairman.css:145`、`:149`、`:215`。

## 功能辨识与信息层级问题

### 6. P2：同页多个“更多”没有对象说明

马匹概况页同时出现两个“更多”：一个用于导出家族模板，另一个是勒令退役。用户必须逐一打开才能知道内容，危险操作与普通导出入口外观完全一样。

建议：合并为唯一“马匹操作”菜单，内部按查看/编辑/导出/危险操作分组；高频功能可直接显示，低频功能收纳。存档卡片上的“更多”需要通过位置或名称明确对应哪个槽。

证据：`audit.json` 中 `dialogBefore.menus`，马匹详情截图。代码位置：`js/chairman-office-ui.js:88`、`:90`。

### 7. P2：评分页面缺少明确的操作顺序和保存状态区分

顶部并列“生成推荐”“采用TF参考基准”“生成整场默认草稿”；每匹马有“保存”；底部还有“保存本场评分”和“修改自动存为草稿”。这些能力有用途，但初次进入时难以判断：推荐是否已经应用，草稿是否算正式评分，单行保存和整场保存有何区别。

手机评分行还同时存在“详情”和“前走详情”。在本次样本中，第一屏主要容纳约两匹马及多个操作，比较整场表现需要反复滚动。

建议：明确为“选基准 → 生成建议 → 调整评分 → 核准整场”四步；持续显示“已存草稿/有待核准修改/已核准”。将单马保存写成“核准此马”，整场写成“核准本场”；当前评分与前走资料分主次，默认保留必要比较数据。

证据：[手机评分页](../artifacts/chairman-ui-audit-20260921/score-mobile.png)、[桌面评分页](../artifacts/chairman-ui-audit-20260921/score-desktop.png)。代码位置：`js/chairman-office-ui.js:68`、`:71`。

### 8. P2：手机的信息压缩依赖过多展开，层级一致性不足

九个主入口下，还存在赛历五个子页、繁殖六个子页、殿堂四个子页；榜单用换行按钮组，另一些用横向标签。筛选又分外层“筛选”、内层“更多筛选”、字段多选菜单。

马匹列表收起时主要保留马名和 WTR/TF，年龄、性别、所属和安排都需要展开。一般看马任务需要这些基础信息，当前“省空间”增加了多次展开和记忆负担。

手机顶栏约高 **174 px**，占 844 px 屏幕约 **21%**；加上页面工具栏与筛选，首屏可用数据区进一步缩小。这是空间利用建议，不单独认定为阻塞缺陷。

建议：先合并同页重复控制，再做轻量分组；不要通过更多嵌套折叠来减少表面按钮数。手机卡片默认显示“马名＋年龄/性别/地区＋关键评分”，展开只放长记录和低频操作。统一子导航样式，压缩顶栏，把存档状态和返回入口放到更紧凑的位置。

证据：[手机马匹页](../artifacts/chairman-ui-audit-20260921/horses-390.png)、[年度奖项](../artifacts/chairman-ui-audit-20260921/awards-390.png)、[血统库](../artifacts/chairman-ui-audit-20260921/breeding-library-mobile.png)。代码位置：`js/chairman-ui.js:67`，`css/chairman.css:173` 起的手机规则。

## 已验证正常、建议保留的部分

- 45 个主要页面/屏宽组合未发现整页横向溢出；桌面马匹表格比较紧凑，不建议直接全部改成大卡片。
- 手机列表第 13 行展开后，进入马匹详情再关闭：滚动位置仍为 859 px，行仍展开，行顶仍在 y=393 px；随后收起时行顶不变。普通行展开收起本身未复现跳位。
- 手机评分弹窗占满视口，底部“保存本场评分”保持可见；应保留固定操作区。
- “更多”菜单支持 Escape 关闭；现有菜单外点击关闭和焦点处理有基础，不必重写整套交互。
- 游戏模式内部配色已基本统一，本轮优先级不在重新制作背景或引入前端框架。

## 推荐实施次序与验收

1. **交互稳定性**：修菜单越界、筛选折叠/草稿丢失、导航活动项不可见、详情弹窗重定位。
2. **功能表达**：合并重复“更多”，明确评分推荐/草稿/核准关系，危险操作单独标识。
3. **信息结构**：统一子导航，减少筛选嵌套，优化手机卡片默认字段与顶栏。

导航可先按用途分组，而不急于删除入口：总览；赛事（赛历/结果评分）；马匹（马匹/繁殖）；荣誉（奖项/榜单/殿堂）；管理（设置/存档）。桌面可保留快速直达，手机用分组导航，避免增加一个必须层层点开的新层级。

验收重点：菜单始终位于可见区域；连续多选无需重复打开；未提交条件不会静默丢失；切页后当前标签可见；详情展开不推动标题和关闭按钮；手机基础马匹信息无需逐行展开；保留列表返回时的滚动/展开状态和评分草稿。
