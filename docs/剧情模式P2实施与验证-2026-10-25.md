分支 `feat/story-mode`，工作目录 `.claude/worktrees/story-mode`。本轮是 P2 的第一批：把 1998 样板年的文本层做实，并完成第一轮平衡。正文全部为 `draft`，等待用户逐条审核（清单见[文本送审清单](剧情模式P2文本送审清单-2026-10-25.md)）。

## 1. 本轮做了什么

### 1.1 共享条件与效果引擎（新增结构）

新增 `js/rules/era-conditions.js`：剧情片段与新闻模板共用的一套**声明式条件语言**。

- 条件键白名单：`eventType`、`tags`、`notTags`、`hasTagPrefix`、`window`、`registered`、`entered`、`rewritten`、`fame`、`horseType`、`rank`、`grade`、`retired`、`deadHeat`、`upset`、`maiden`、`starts`。
- 效果白名单：`fame`（名声增减）、`tag`（加标签）、`media`（媒体口径 quiet/confident）、`relation`（与某匹马建立 rival/nemesis 关系）。
- 不使用 `eval`；`validate()` 会在拼错键名、值类型不对、效果类型未知时给出告警，剧情片段在告警非空时直接拒绝加载。
- 上下文全部由**不可变事件流**推导：标签、名声、进入过哪些比赛、是否改写过冠军，都从 `run.events` 重算，读档后可以逐字复现。

**结构变化说明（按约定先在方案里说明）**：第 3 节的文件表已补上这一行。

### 1.2 按年份拆分新闻与百科

- 新增 `js/data/era/news/<年>.js`：逐年登记“每场年鉴收录前五赛事的史实简讯”。1998 年 29 条。
- 新增 `js/data/era/almanac/entries/<年>.js`：年鉴里的百科条目（名马 / 名场面 / 年度）。1998 年 28 条，注册表新增 `registerEntries / entriesOf / entry` 与对应校验（未知马匹、未知赛事、类别非法、正文缺失都会告警）。
- `js/data/era/news-templates.js` 扩到 26 条模板，覆盖比赛结果的全部类型（取胜/爆冷/初胜/未分级胜/同级/次席/季席/落败/同着/退赛/未参赛）与专题报道（三冠、三冠候选、丢冠、复出、不败、连胜、连败、改写者、宿敌、克星）。

### 1.3 剧情片段与正文

- 1998 年 16 个剧情片段（`js/data/era/storylets/1998.js`），18 段场景正文（`js/data/era/texts/1998.js`）。
- 赛前片段只写**出走表**（赛前公开信息），不透露史实赛果；赛后片段才引用名次。
- 新增 `triple-crown` 片段与 `jp.era.1998.scene.triple-crown` 正文：三冠达成是本局世界线改写，正文会写明 1998 年史实里没有三冠马。
- 新增三冠专题报道，并把旧模板里“史实的三冠由别的马完成”改为“1998 年的史实里没有三冠马”。

### 1.4 界面

- `js/ui/era-render.js` 增加“1998年鉴 · 百科”区块，每条对照显示“史实冠军 / 本局冠军 · 玩家名次”；未参赛的条目标注“本局：玩家未参赛，按史实推进”。
- `css/era.css` 适配新区块（桌面、手机宽度均无横向溢出）。

### 1.5 第一轮平衡

只动了一个数：`js/data/era/horse-types.js` 里王道型牡马的 `strengthMin/strengthMax` 由 **81–85 改为 83–87**。

理由：实测玩家表现分与史实分差在 −3.7（皋月赏）到 −8.3（有马纪念）之间，古典赛胜率被压到 11.2%，三冠组合概率约 0.2%，属于“理论上可达、实际见不到”。上移 2 点后三场古典赛难度趋于接近（菊花赏仍最难，因为 1998 年那一场的史实前五确实最强），三冠组合概率进入 1%–2% 区间。

**本轮不动**：史实表现分（`js/data/era/race-performances/1998.js`）是史实侧标定值，不为凑胜率修改；玩家骑手能力、资格规则、7 日间隔也不动。

## 5. 未覆盖项与未完成项

1. **正文全部是草稿**，等用户审核后改 `final`；审核清单已按 ID 排列。
2. **史实准确性只做到“与年鉴一致”**。百科与新闻里的每个事实都取自年鉴数据（马匹档案、前五名次、赛事日期场地），并抽样对照 JRA 官方结果页；但只对照了 1998 年三场古典赛与部分 G1，其余 117 场没有逐场人工核对 JBIS。测试通过不能替代史实核对。
3. **“二岁、四岁衔接”尚未做**。方案 P2 写了“完整走完 1998 年及其前后的二岁、四岁衔接”，目前只做了 1998 年本身；1997（二岁，1995 年马出赛）与 1999（四岁）需要各自的赛历与年鉴数据，属于 P3 的“按年份逐步加入 1996–2000 赛历和出走表”范围，界面上明确写着“1997/1999 尚未接入本原型”。**这一条没有完成，不能算 P2 收尾。**
4. **人物（骑手/练马师中文名）与年表模块未做**。理由：没有权威中文名来源，全球骑手库也没有中文名，年鉴里保留日文原名不臆造译名。
5. **名骑邀约（骑手主动邀约）未做**：需要改存档结构，会动 `RUN_VERSION`，按约定不在本轮做。
6. **平衡只覆盖王道型一种马**。“各类型马难度相当”要等另外三种马加入（P3）后重测；现在的数值随时可能被新类型推翻。
7. **胜率对数值敏感**：古典赛平均胜率在 81–85 是 11.2%、在 82–86 是 17.1%、在 83–87 是 22.8%，两点能力改动就能翻倍。P3 补 1997/1999 数据后需要重跑平衡。
8. `js/data/era/golden-road-1998.js` 是 P1a 的旧剧本文件，已不被 `index.html` 加载、也不再被任何代码引用，方案第 3 节原计划“新剧本上线后删除”，本轮未删（避免越过本线范围删文件）。
