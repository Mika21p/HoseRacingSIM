## 1. 项目目标与玩法定位

新增一个基于项目现有赛马引擎的长期沙盒模式。玩家扮演类似国际赛马评定机构主席与赛马会主席的角色，建立赛马世界并为比赛表现作出评价。

核心职责：

1. 建立赛马场，设置赛事与年度赛历，创办有持续历史的大赛。
2. 观察自动生成的AI马匹参赛，以及马匹、骑手、马主和血统的长期变化。
3. 根据公开比赛表现评定WTR，或采用机器评分。
4. 评选年度奖项、决定殿堂荣誉，形成可回顾的赛马历史。

自建马匹、指定配种、勒令参赛、恢复状态、修改属性等属于额外的“上帝操作”工具。它们可以丰富实验与观察，但不应成为推进世界的必要操作。

核心循环：

**设置赛场与赛历 → 自动生成／成长／繁殖 → AI报名与休整 → 现有引擎模拟 → 半月结果汇总 → 主席评分 → 年度评奖与历史归档。**

主要体验：

- 世界能够自行连续运行多年，玩家可以轻度参与，也可以认真逐场评定。
- 真实能力隐藏，玩家根据表现作出判断；高能力不一定立刻获得高评价。
- 不同地区、赛场、赛历与马主偏好提供不同机会，产生“生错地方”“距离路线不合适”等故事。
- 强马长期更容易证明实力，但单场失常、晚熟、转变参赛路线等保留悬念。
- 自创马与其他马遵守同样的模拟规则；它的后代可以继续被观察。
- 没有马会资金压力。奖金用于参赛吸引力、成绩统计与荣誉比较，不作为强制经营负担。

不作为首版核心循环的内容：逐匹训练、人工处理日常配种、逐匹选择骑手、靠复杂议会操作才能推进时间。相关功能应自动运行或作为附加工具。

## 2. 决策状态与优先级

### 2.1 已明确确认的方向

| 编号 | 决定 | 开发含义 |
| --- | --- | --- |
| C01 | 以项目现有核心引擎为主适配 | 不照搬参考中的另一套比赛公式；共用基础规则，扩展新模式的组织与结算方式 |
| C02 | 沿用半月制 | 每年12个月，每月上、下半月，共24个常规回合；保留接入现有史实赛事的空间 |
| C03 | 主席是组织者与评定者 | 主要入口围绕赛事、赛场、结果、评分、奖项与历史 |
| C04 | 自动马群是主要参赛者 | 每匹马持续存在，有生涯、状态、后代与成绩；不能只为一场比赛临时补出无历史对手 |
| C05 | 真实能力默认隐藏 | 自创马例外；普通生成马、自动繁殖后代不因与自创马有关就自动公开真实能力 |
| C06 | 手动评分与机器评分并存 | 玩家不手动评分时，世界仍能正常运行；最终评级采用方式见评分章节 |
| C07 | 自动繁殖，允许指定 | 自动繁殖负责换代，指定配种与自建马同属附加工具 |
| C08 | 半月回合汇总 | 主要操作节奏为回合结束后集中查看与评定；重大G1应获得明显展示 |
| C09 | 支持十几匹真实马同场 | 扩展全场参赛与完整名次，不沿用只关注前五或少数对手的展示限制 |
| C10 | 加入轻度失常，例如G1压力 | 只影响本场发挥，具体概率、幅度与条件需要模拟校准 |
| C11 | 新模式取消60能力硬下限 | 排查赛前能力、未成熟阶段等相关保护；不意味着改变随机基础能力分布 |
| C12 | 优化大型本地存档 | 新模式不能继续每次重写整个世界对象；采用适合长期马群与赛史的数据组织 |
| C13 | 自建马与自建比赛支持导入导出 | 支持玩家在本地表格编辑、批量导入与分享 |
| C14 | 保持沙盒自由度 | 不依靠隐藏的资金限制迫使玩家管理，不因遗漏人工操作卡住世界 |

### 2.2 推荐作为实现基线、细节尚可调整

- IndexedDB分项存储、增量提交，搭配独立的完整存档文件导入导出。
- Excel作为完整创作模板，CSV支持简单批量编辑。
- 隐藏精确竞技属性，公开身份、赛绩、血统与比赛条件；AI通过不完全准确的估计逐渐调整选赛。
- 机器建议分与玩家官方分分别保存；无人处理时可自动采用机器建议，手动修订不被机器静默覆盖。
- 默认提供可运行的赛事与初始马群模板，也允许空白创建。
- 普通赛为新马和较弱马提供参赛渠道，重要赛事由主席重点设计。
- 后台保存出生批次，到龄加入出赛马群；自动补充与退役维持长期运行。
- 正式成绩事实、公开列表显示、统计汇总相互区分。
- 旧模式保持既有行为，新模式采用明确的模式配置，不通过全局修改意外影响旧存档。

### 2.3 原参考中不得直接视为最终规则的内容

- 每月四周、按周设置巅峰期及相关概率：应转换到半月制或重新定标。
- 能力＋适应性＋4d5、G档扣15、增程3x−1、统一每2分一马身等：不替换现有引擎。
- 骑手取位阈值使用能力一半：不替换现有能力三分之一的对应规则。
- WTR、TF的120／128／136，以及能力80／84等门槛：可保留为参考值，需验证新模式尺度。
- 造时直接按最终得分100为基准、每分0.5秒：只作为参考方案，尚未确认参数。
- 所有关于具体概率、继承强度、出赛间隔、投票门槛和排名展示阈值的建议，未经确定不得写成现实规律。

- 现有传奇对手选择常量为5；部分流程还会加入玩家马或隐藏对手。不能把它理解为已经支持任意规模世界马群。

- 现有玩家马与对手的能力准备、伤病后处理存在不同路径，需统一。
- 现有史实固定得分分支适用于原模式语境；主席模式中的真实在籍马默认按统一引擎重新比赛。
- 现有生成血统ID主要是模板身份，不能直接当成真实父母马ID复用。
- 检查到的生成与比赛计算尚未构成参考方案所说的完整跑法适应性系统。新增跑法必须先定义实际机制。

## 4. 时间、回合与年度结算

### 4.1 半月推进

每年为1月至12月，每月上、下半月。核心按钮采用“下一回合”等清晰措辞。

常规回合建议顺序：

1. 展示本回合赛事、预计出马表与重要G1。
2. 玩家编辑赛事、处理评分或使用附加工具。
3. 推进时锁定本回合正式参赛信息与比赛条件。
4. 自动分配骑手，模拟各场比赛，保存所有参赛成绩。
5. 更新奖金、系列赛、评级建议、马匹状态与各项统计。
6. 展示半月汇总；玩家可以逐场审阅、重点评分或采用机器建议。
7. 为恢复且未安排比赛的现役马重新规划参赛。

评分发生在结果产生后；已完赛比赛的负重、名单、胜负不随随后改分倒推变化。新评分对哪些未来报名生效，应通过锁定时点统一处理。

### 4.2 年末回合

12月下半月比赛结束后，增龄前进入年末回合。年末不是额外半月，不再次推进成长、休养或比赛。

建议顺序：

1. 完成本年比赛与系列赛结算。
2. 展示年度回顾、评级、主要成绩和奖项候选。
3. 玩家补评分、保存颁奖名单、颁奖、决定荣誉；启用议会时使用本年同一轮有效投票记录。
4. 点击结束年度后，归档年度WTR／TF、奖项、系列赛积分、排名和统计。
5. 清空新年运行所需的年度计数，不删除历史。
6. 增龄、处理自动退役、繁殖年度事件和新马出道，进入下一年1月上半月。

配种、出生、出道和繁殖退役的精确先后需在实现繁殖时统一，避免同一年度重复执行。

### 4.3 快进

- 支持推进到下一场赛事／下一个关注事件。
- 重大G1强调展示，是否每场强制停下由玩家设置。
- 年末、需要玩家处理的事项应成为停止点。
- 快进仍逐步结算成长、恢复、配种、出生等，不直接跳过中间状态。
- 允许中止快进，每个完整回合有清晰保存边界。

## 5. 世界结构与归属

### 5.1 基本对象

- 世界：年份、当前半月、规则版本、生成政策、随机状态。
- 主马会／子马会：名称、偏好、所属赛事、骑手与荣誉管理。
- 马场：名称、地理地区、场地及现有引擎能支持的赛道特征。
- 马主：姓名／代表人、所属马会、冠名、参赛偏好。
- 马匹：真实属性、出生年份、生涯状态、马主、直属马会、亲缘、历史成绩。
- 骑手：能力、所属马会、分配信息、成绩与奖金统计。
- 赛事定义：长期重复举办的赛事规则。
- 年度届次：某项赛事某年实际举办的比赛。

马会行政归属与引擎地理赛区独立。改变所属马会，不应自动改变地区适应性、远征目的地或草泥地类别。

### 5.2 历史快照

比赛成绩保存当时马主、马会、骑手、马场、条件与赛事版本。转会、改名、改条件不重写旧成绩。

“现有成员贡献”与“当年代表本马会取得的成绩”应标注统计口径，避免互相混淆。

### 5.3 默认世界与空白世界

建议提供一套能直接运行的基础世界，以及完全空白创建选项。普通赛承担新马、较弱马和非主流距离马的参赛需求；玩家重点建立大赛，也可调整全部赛事。

赛历应帮助检查赛事密度、距离／年龄／性别覆盖及长期无赛可跑的马群。创办赛事可预览当前符合条件的马匹数量。

## 6. 马匹生成、隐藏信息与玩家工具

### 6.1 生成方式

- 自动生成AI马，默认由世界自行补充新世代。
- 全随机马：原参考要求生成二岁马，随机名称、性别、能力、适应性与巅峰期；新模式属性采用现有引擎。
- 批量生成：数量可配置，分批执行并显示进度，避免界面冻结。
- 自建马：玩家自由填写受支持的属性、身份及血统。
- 表格导入：新增或更新自建马，见第18章。
- 育成强化、早熟倾向、牝马能力分布偏移等保留为可选生成政策，默认值与是否首版采用待定。

性别包括牡马、牝马、骟马；骟马随机概率较低，具体概率未定。骟马不进入繁殖。

### 6.2 信息边界

| 信息 | 默认可见性 |
| --- | --- |
| 名称、年龄、性别、毛色、马主、马会、血统 | 公开 |
| 赛绩、奖金、骑手、比赛条件、玩家评分、荣誉 | 公开 |
| AI马真实基础能力 | 隐藏 |
| 精确适应性、距离范围、巅峰期、内部惩罚与骰值 | 推荐隐藏，最终字段白名单需统一 |
| 自创马参数 | 玩家已知，可查看自己填写的参数 |
| 自创马的自动繁殖后代 | 默认仍隐藏真实能力 |
| 适距、成熟、场地偏好等推测 | 可根据已观察赛绩提供，允许不确定和错误 |

不要通过筛选、排序、导出、说明文字或诊断提示间接泄露默认隐藏的属性。内部调试信息与正式玩家界面分开。

自创马可作为已知能力样本，用来观察真实能力、环境与WTR之间的关系；不能获得额外模拟优待。

### 6.3 附加工具

- 自创／编辑马匹、指定配种、指定归属。
- 勒令参赛、特批参赛、英雄集结。
- 勒令退役、指定殿堂／子殿堂、特批百大。
- 妙手回春：清除指定马的当前休养限制。
- 一鼓作气：批量清除马匹休养限制。
- 基因／属性修改作为明确的沙盒操作，影响未来，不重新模拟历史。

是否允许特批跨越退役身份、伤病、同回合重复参赛等，需分别定义；不能用一个含糊的“忽略所有条件”包办。

## 7. 马场、赛事与年度届次

### 7.1 创建与编辑

赛事基础字段：

- 名称、格付（G1／G2／G3；推荐同时支持现有普通赛事类别）。
- 马场、地理地区、草地／泥地、距离（米）。
- 举办月份、上／下半月。
- 年龄条件：二岁、三岁、四岁限定；二岁及以上、三岁及以上、四岁及以上。
- 性别条件：牝马限定、牡马限定、骟马限定、牡牝、牡牝骟全开放。
- 一至五着奖金（万），支持直接填写与按比例分配。
- 参赛上限、优先出走、核心大赛标识等按后续规则开放。
- 标准造时及负重制度为候选扩展，见后文。

条件可选项：

- 生涯最高WTR达到指定值。
- 指定系列赛本年积分达到指定值。
- G1胜场或奖金达到指定值。
- 曾在指定赛事获胜／前二／前三。
- 非开放：仅允许与比赛同马会的马匹报名。

多个勾选条件默认全部满足；指定多个历史赛事时“任一／全部”还需明确。

### 7.2 重复举办与修改

- 创办的是长期赛事，每年对应半月产生一个年度届次。
- 日期尚未过去可本年举办，已过去从下一年开始。
- 同一赛事同一年不因改期重复结算。
- 编辑影响尚未锁定的未来比赛，历史成绩保留旧条件。
- 删除赛事停止未来举办；过去成绩、奖金与荣誉继续存在。
- 删除被系列赛引用的赛事时，必须处理当年系列赛如何结束及未来定义。
- 参赛为零时取消；单马独走是否给奖金、G1胜场及系列赛积分待定，不能隐含处理。

### 7.3 马场历史

展示代表大赛、历届冠军、纪录、经典对决及擅长本场的马。马场差异应由引擎已有的地区、场地与赛道机制产生，不能只有名称区别。

## 8. AI排赛与报名选拔

### 8.1 选赛原则

AI按参赛资格与可达性筛选，再综合休养、对适应性的估计、系列赛目标、格付、奖金、竞争强度、马主倾向、马会偏好及少量随机因素。

不得直接把真实隐藏属性转化为永远最优的路线。AI可依据血统先验和比赛经验逐渐修正判断，也可能因偏好和赛事供给长期错配。

马会／马主偏好只改变参赛意愿，不改变引擎里的实际适应性惩罚。

### 8.2 避免长期闲置

- 每回合检查所有未安排比赛、且具备出赛条件的现役马。
- 新生成、落选、赛事取消或恢复后的马重新进入排赛。
- 等待理想比赛过久时，逐渐放宽适距要求；原参考“超过12周”在半月制下需统一为约三个模型月的明确阈值。
- 使用实际增程与缩程惩罚估计风险，不把上下偏离400米机械看成一样。
- 弱马可偏好报名较少、竞争较轻的赛事；保留普通赛与开放机会，避免低评级马被永久排除。
- 奖金有吸引力，但避免极端奖金完全压倒其他因素。

### 8.3 报名满额

推荐使用“提交意向 → 统一选拔 → 落选者找备选”的流程，减少依次顶替引起的遍历顺序偏差。

候选优先级可包含优先出走、WTR、奖金及同分规则。原参考提出WTR更高可顶替最低者，同WTR比较奖金；最终选拔规则需明确无评级马与占位情况。

玩家勒令参赛锁定席位，AI不得再次挤走。超额时如何替换或扩容，应作为显式规则。

英雄集结参考：先清空原名单，筛选符合资格且对应场地至少C、距离在射程内或偏离不超过400米的马，按WTR优先，缺额再按TF、奖金、能力补报。默认隐藏能力环境下，该工具如何展示排序依据需调整；不能借此公开真实能力。

### 8.4 偏好与可解释性

马会可勾选：短途、英里、中距离、中长距离、超长距离、草地、泥地狂热。

马主可设置−100至+100的历战、各距离、草泥地、系列赛、牝限、跨距离及远征倾向。推荐保留偏好上限，防止同时勾选导致全盘压倒合理性。

原参考遗漏或混用了“长距离／超长距离”，距离分类应统一，边界不得重叠或留空。

可显示基于已知信息的报名理由，如争取系列赛、休整后复出；不要显示精确隐性适应性或能力惩罚。

## 9. 多马模拟、轻度失常与取消60保底

### 9.1 统一参赛处理

每匹真实参赛马都计算自身成长、适应性、气性、疲劳、骑手、比赛阶段与赛后状态。共享同场场地状况等公共条件，个体随机分别产生。

输出完整名次、相邻／距冠军着差的清楚口径、骑手、奖金、机器评分与赛事评分。退赛状态与最后一名分开。

大马群本身会放大名次波动；名次靠后不等于严重失常。机器评分不得只根据名次线性扣分。

### 9.2 已确认的新模式调整

- 取消修正后有效能力最低60的保护。
- 同时检查未成熟阶段最低60及其他类似保护，不漏改、不影响旧模式。
- 不把取消保底等同于更改基础能力随机分布。
- 极端输入及造时等输出合法性单独校验，不以恢复60保底掩盖问题。
- 在原比赛阶段之外，考虑轻度G1压力导致的本场失常。

### 9.3 G1压力推荐初稿

- 每匹马独立判定；首次参加G1者概率略高，有一定经历后适度降低但不完全免疫。
- 可与气性小幅关联，避免与原气性、疲劳、骑手失误重复扣罚。
- 仅影响本场表现，不永久降低基础能力，不自动触发伤病或退赛。
- 初始试验范围：概率约5%～10%，扣减约3～8分。**这些数值尚未校准，不是最终规则。**
- 不规定每场必须失常几匹，也不引入同等规模的巨大正向爆发。
- UI不直接揭示真实扣分；只提供由表现支持的观察性描述。
- 先观察取消60下限后的分布，再确定压力幅度，避免同时过度扩大负面波动。

### 9.4 讨论期间的模型核对结果

对现有普通模拟马，固定赛前能力、骑手能力70、普通冲刺，仅枚举出闸／取位／冲刺，得到：

| 指标 | 结果 |
| --- | --- |
| 完赛者比赛阶段总修正均值 | 约12.04分 |
| 完赛者阶段修正标准差 | 约4.22分 |
| 比自身平均低至少10分的完赛表现 | 约1.02% |
| 单马因三个阶段判定未完赛 | 约2.97% |
| 16匹独立同类模拟马中至少一匹未完赛 | 约38.27% |

这些是特定模型条件下的计算，不是现实统计，也不是全模式长期测试。未加入赛前条件变化、额外疲劳事故或史实固定得分分支。说明需要区分“失常但完赛”和“事故退赛”，不能只继续增加事故。

### 9.5 调整后的验证场景

- 实力接近的大马群。
- 强弱分明的比赛。
- 严重不适合距离／场地的马。
- 年轻未成熟、衰退、疲劳与G1初参赛马。
- 对比强马胜率、前后马群着差、完赛失常率、退赛率、评分分布。

## 10. 骑手、疲劳、伤病与休养

### 10.1 骑手

保留原引擎的向下取整10%能力加成及出闸／取位／冲刺流程，不再叠加参考中的第二套骑手随机加成。

候选管理功能：

- 新增、编辑、搜索骑手，设置名字、能力、所属马会。
- 按年展示胜场、G1胜场、奖金、1－2－3－其他成绩，按胜场排序。
- 点击查看历史胜场、胜率、G1数与奖金。
- 马匹优先延续上一场骑手，再从符合条件的马会骑手中分配；可以使用能力权重，但需避免只服务高评级马导致长期固化。
- 同一场比赛一个真实骑手只能骑一匹马；不足时使用相互独立的占位骑手。参考能力30尚待定标。
- 同一半月多场比赛如何安排骑手行程需统一，不直接把“同半月”等同于“同一时刻”。

### 10.2 疲劳与伤病

- 常规休养决定AI最短出赛间隔，历战倾向影响主动休整意愿。
- 继续承担现有引擎的疲劳与事故后果，不新增不透明重复风险。
- 伤病概率设置若保留，必须说明它控制现有风险还是额外风险；参考默认0%不能含糊解释。
- 参考“额外1～48周修养”需按半月制与原伤病等级适配。
- 强制退役等影响较大的事件建议有模式开关。
- 妙手回春等工具只改变当前限制，不删除历史伤病事实。

## 11. WTR、机器评分与年度记录

### 11.1 数据概念

- 真实能力：隐藏的引擎属性，不由评分直接改变。
- 机器单场建议分：系统对当场表现的评估，保存后不因打开页面重新抽取。
- 玩家赛事分：玩家对该马该届比赛的评价。
- 本年WTR：本年度官方整体评价，可修订。
- 年度历史WTR／TF：年末封存的年份记录。

首轮已确认：无人手动处理时采用机器TF及自动年度建议；玩家年度WTR修订具有最终优先权，系统只继续更新建议。后续可研究不同的机器评价方法。

### 11.2 参考TF公式与后续讨论

原参考：每场抽取一次整数浮动−5～+5，同场共享；单场TF＝最终比赛得分＋10＋浮动，年度TF取本年最高值。

适配边界：

- 无有效完赛得分者不生成该场TF；没有出赛的年份不显示年度TF。
- 直接映射内部得分会提供很强的隐藏信息，并受到原引擎分数尺度影响。
- 首轮选择内部得分TF作为试验公式。以后可研究依据公开名次、着差、对手既有水平及多场表现的算法；不得静默重算已经封存的旧记录。
- 造时若同样从内部得分推导，不能当作完全独立证据重复加分。
- 可展示近期表现、年度均值或可信程度辅助理解，年度最高值与长期稳定性分开。

### 11.3 手动WTR联动

原参考要求填写赛事分后，若高于本年WTR或本年WTR为空，则自动读取本年最高赛事分。

首轮已确认：人工年度WTR可以低于最高赛事分。赛事分修改仅重算该年度的建议，已有人工年度覆盖不变；恢复自动评价只清除人工覆盖。

原参考规定历史年度WTR仅在历史榜修改，后文又提出在马匹页面修改年度评分；需统一编辑入口和权限。推荐多个入口编辑同一记录，明确年份，禁止误改当前年度。

### 11.4 历史与比赛页面

- 比赛结果显示各马此前最近一次出赛的赛事分，缺失值不当成0。
- 既往赛事分可在比赛或马匹记录定位编辑，官方评级是否随历史修订重算需明确。
- 年末封存后的历史记录不随下一年度变化自动覆盖。
- 新年度本年评级为空，但AI和报名可以明确参考上年评级；本年榜只按本年口径展示。
- 重拟评分清除玩家本场评分与相关草稿，不改比赛结果；机器建议保留，是否回退官方值需清晰显示。
- 评分只影响制度明确规定的未来资格、优先级或让磅，不替换真实能力。

### 11.5 榜单

- 本年WTR榜：现役且有本年评级的马，展示本年G1胜场。
- 历史WTR榜：以“马匹＋年份”为条目，同一匹马可占多个年份。
- 奖金榜：区分本年、历史总奖金；马主／骑手／种马另有统计。
- 年龄、性别、马会等筛选保留状态；历史年龄按记录年份计算，不按当前年龄。
- 原参考默认前十，“展开”为本年≥120、历史≥128，“完全展开”为≥115；这些是待校准阈值。“完全展开”若仍排除低分，需要改名或真正支持查看全部。
- 推崇TF：仅在明确指定的荣誉资格、候选筛选、投票中允许替代WTR，不能自动改写所有让赛与入场规则。
- 隐藏能力环境下，TF是否公开取决于最终算法；不得通过TF筛选与排序泄露被隐藏的同一数据。

## 12. 系列赛、年度奖项、殿堂与排名

### 12.1 系列赛

- 自定义名称、奖金、任意现有赛事、各场名次积分。
- 年龄限定：2岁／3岁／4岁／不限，资格按当届比赛年龄判断。
- 系列赛模式：末站后累计积分最高者获得奖金与冠军称号。
- 三冠模式参考：累计积分达到玩家门槛者获奖，可多人达标或无人达标；不是默认三场全胜。
- 获胜后AI提高参加后续场次的意愿，但不自动无视资格与健康。
- 支持编辑、删除；当年已经得分后的规则修改生效边界需明确。
- 推荐并列最高可共同冠军，全员零分不产生冠军，多人达标奖金是否每匹全额需明确。
- 年末清空新年积分，保留历年积分榜、冠军与奖金。

### 12.2 年度奖项

玩家有最终决定权，机器与议会只提供建议或一键采用结果。保存未完成颁奖草稿，候选显示当年所胜G1名称与投票信息。

参考严格候选规则：

| 奖项 | 参考资格 |
| --- | --- |
| 最佳短距离马 | 本年赢过短途或英里G1 |
| 最佳中距离马 | 本年赢过中距离或中长距离G1 |
| 最佳长距离马 | 本年赢过中长距离或长距离G1 |
| 最佳草地马／泥地马 | 本年赢过对应场地G1 |
| 年度代表马 | 本年赢过G1 |
| 最佳2岁、3岁、4岁以上牡／牝马 | 对应年龄性别且本年赢过G1 |

推荐统一“严格／宽松／主席特批”候选范围，取代重复且冲突的筛选／弱化筛选开关。宽松只放宽G1要求，保留奖项类别条件。

骟马归入哪类性别奖项、长距离与超长距离关系、世界马王定义尚待确定。

奖项页面默认本年与去年，提供按年份回顾。允许评语及代表赛事关联。

### 12.3 主殿堂、子殿堂与百大

三种独立信息，共用界面但分开存储：

- 主殿堂：全局荣誉身份。
- 子殿堂：直属子马会授予的地方身份。
- 百大／殿堂排名：排序，可以包含特批现役或非殿堂马。

候选从退役马产生。参考淘汰条件为同时满足：无G1、无主马会年度奖项、WTR＜120、无称号；只移出候选池，不删除马匹、生涯或血统。

子殿堂自动资格参考：G1≥7，或WTR≥136，或入选主殿堂；仅对直属子马会者执行。推荐使用生涯最高已记录评级，入选后不因改分、跨年或转会自动撤销。玩家可指定入选。

参考后期要求子殿堂候选只来自主殿堂候选，与可能现役自动达标的逻辑有冲突；自动授予是否必须已退役待定。

筛选“年度奖项”“殿堂马”默认只含主马会荣誉，另有“获子马会奖项”“入选子殿堂”。子殿堂移至殿堂页面，子马会详情保留统计，不强制罗列全部所属马。

排名与普通列表排序分开，按WTR浏览不能改变正式NO.1等。允许手动调整正式顺序、议会生成排名、特批百大；保存年度排名用于↑／↓／新入榜比较。

殿堂卡片仍可进入马匹信息，展示战绩、奖金、评级、全部G1胜利、称号、系列赛冠军、世界马王和年度奖项。

候选列表参考默认前十，可展开，支持WTR／G1／胜率／奖金／最近殿堂得票率倒序。

批量移除候选参考筛选：胜率＜50%、WTR＜128、能力＜90、G1≤2、无年度奖项、无年度代表马、无世界马王。正向筛选含相反门槛及系列赛冠军等。隐藏能力模式不能提供能力筛选；多个筛选的交并关系必须明确。

## 13. 议会与下属投票（后续扩展）

不作为第一版世界运行的前置条件。

### 13.1 下属类型

允许添加、编辑、删除类型，设置人数（非负整数）、每人投票权重（可小数）与倾向比例，总和为100%。

参考倾向：

- G1数最多、WTR最高、奖金最高。
- 随机、弃票。
- 延续：投给去年对应对象，失效时重新选择有效倾向。
- 称号：按符合范围的称号数量加权抽选，无人符合则弃票。
- 胜率最高。
- 荣誉：系列赛冠军、世界马王、年度代表马；年度奖项投票按当年范围，原参考只计当年系列赛与世界马王。

称号／荣誉计数以明确结构化记录为准，不能把重复显示文本当成多项荣誉。胜率倾向推荐设最低出赛次数，数值待定。

### 13.2 投票流程

- 年度奖项：使用与颁奖界面一致的候选池，G1／WTR／奖金／胜率取本年。
- 殿堂：使用候选池与生涯指标，展示最近得票率。
- 议会殿堂：超过设置门槛自动入选；参考使用严格“超过”，是否改为≥需明确。
- 议会百大：从第一名逐轮投票，胜者移出本年后续轮次，直至100名或无人可选；允许特批百大对象参与。
- 通过投票：将年度奖项最高票者填入颁奖名单，玩家仍可调整；并列处理需定义。

推荐以全部投票权重（含弃权）为得票率分母，零权重不产生结果。年末自动与手动投票共享本年记录，打开页面不重投、不重复授奖。若允许主动重投，应明确取代哪轮结果。

## 14. 自动繁殖、真实血统与后代观察

### 14.1 自动换代

- 后台负责配种、出生批次与到龄出道，玩家无需逐匹操作幼驹。
- 玩家可指定配种或导入自建血统，属于附加工具。
- 当前参考默认每年自动产马30，可自由设置非负整数；最终默认量需结合赛事供给与性能确认。
- 区分出生数量、到龄出道数量与直接生成二岁马的工具数量。

### 14.2 个体亲缘与遗传

- 每匹马保存真实父母ID，三代血统展示由关系展开。
- 父母提供主要遗传倾向，祖辈提供较弱影响，保留个体随机差异。
- 倾向包括草泥地与地域适应性、距离、成长、气性及已有引擎支持的其他特征。
- 不把每代能力做固定累加，不保证强父母一定生强后代。
- 祖先重复出现不能被当成互相独立的增益不断叠加。
- 子代马主随母是原参考建议，可作为默认政策；转移与指定应保留空间。

### 14.3 繁殖资格参考

- 牡马退役且至少1场G1胜利成为种牡马。
- 牝马退役且至少1场胜利成为繁殖牝马。
- 繁殖能力可手填，随机1～100；原含义为被选为父母的概率权重，建议命名为配种权重并与遗传质量分开。
- 父亲按合资格种牡马权重抽取，母亲按合资格繁殖牝马权重抽取。
- 同一母马同一出生年份仅一个产驹。
- 缺少父母时使用外来／输入繁殖马占位，不影响其他属性也不进入真实祖先比例计算。

原参考“繁殖前四年无产驹且不会繁殖退役”“每年以1＋floor(年龄／10)%繁殖退役”均需重新适配。必须先区分配种年、出生年、出道年，不能让刚退役马立即拥有二岁子代。

### 14.4 亲缘约束

- 防止自己成为自己的祖先，避免循环关系。
- 检查父母年代与性别，手动指定冲突要给明确提示。
- 原参考祖先占比超过50%重抽属于简化约束，不等于完整近交系数。
- 需要明确重复路径贡献算法；达到重试次数上限后使用外来血统，不能无限循环。
- 家谱术语按正确亲缘显示：若A的父亲为B，C的父亲为A，则B是C的父父。
- 繁殖退役不删除祖先资料。

### 14.5 玩家观察与统计

- 搜索种牡马／繁殖牝马，查看血统、本年与历代WTR前十子代。
- 展示子代、孙代、代表后代、首个G1后代、累计胜场与奖金、家系延续代数。
- 本年子代奖金前十种牡马／繁殖牝马榜。
- 年末子代本年奖金第一的种牡马获冠军种马，累计次数可查看。
- 种马历史榜按直接子代生涯总奖金排序；不能默认把所有后代重复计入直接子代统计。
- 勒令繁殖退役及批量条件：种牡马G1＜2、WTR＜120、子代本年奖金非零但低于指定值；牝马G1＜1、WTR＜120。规则为参考，阈值与交并关系待定。

## 15. 负重制度（候选引擎扩展）

参考包含以下制度，尚未确认首版全部实现：

1. 基础负重：二岁、三岁、四岁及以上牡马各一值，牝马按同龄减重，骟马默认按牡马。
2. 别定：G3／G2／G1获胜、指定系列赛冠军等增加负重。
3. 评分让赛：设最高／最低负重，按本年WTR差每分0.5kg调整，选择优先最高或优先最低。

原模拟修正：同场最低负重者不变，其他马每高0.5kg减1能力。此项会改变胜负，应作为明确引擎扩展独立评估，不直接因为参考存在就叠加。

推荐三种模式有清晰优先关系：基础；基础＋别定；或评分让赛直接决定最终负重。避免让赛封顶后再加别定而突破上限。

别定中重赏加重建议取符合条件最大值，系列赛另算；是否累计、同一荣誉多次获奖是否重复，需明示。输入建议0.5kg步长。

无可用评级的马不能自动参加评分让赛。新年使用上年评级还是等待本年评级、主席特批如何赋重，需与第11章统一。

## 16. 标准造时与纪录（候选展示扩展）

### 16.1 参考规则保留

- 创建／编辑赛事时填写分、秒、百分秒，参考输入上限9:59.99。
- 设标准为T、冠军最终得分为S。
- S＝100时，在[T−1秒，T＋1秒]随机。
- S＞100时，下界为T−1−0.5×(S−100)秒，上界仍T＋1秒。
- S＜100时，下界仍T−1秒，上界为T＋1＋0.5×(100−S)秒。

### 16.2 推荐适配

- 不让造时反向决定名次；先由现有引擎决定比赛，再生成展示时间。
- 原方案高分会扩大区间，而不是整体平移；0.5秒系数对短长途影响不同，需校准。
- 推荐按距离、表现与场地状况计算修正，加少量随机波动。
- 编辑标准后历史届次仍保留当时标准与实际造时。
- 非标准距离可采用相邻参考距离插值；参考原文“取最近距离”保留为可选，但最终统一一种方式。
- 统一加慢4.5秒是参考表的一次版本变更，不能每次导入反复相加。

### 16.3 查询与展示

- 结果显示本届胜马造时与当时标准。
- 赛事信息显示历史最快、最慢胜马造时。
- 造时记录可组合任意筛选：场地、精确距离、马会、马场、格付、具体赛事。
- 固定显示1200／1600／2000／2400米纪录卡片。
- 区分“每项赛事最快纪录”与“历次造时”，避免名为全部却只给一条。
- 删除结果列表显示不应破坏官方纪录事实。

## 17. 界面、查询与历史数据

主要入口建议：赛事与马场、半月结果汇总、评分工作台、年度奖项、榜单、历史与殿堂。繁殖与归属提供观察页面；上帝操作集中到沙盒工具。

通用要求：

- 所有榜单、出马表、结果、评分、奖项、投票界面的马名可进入同一个马匹详情。
- 马匹、比赛、结果按名字搜索；统一年龄、性别、场地、距离、归属、荣誉等筛选。
- 筛选、排序、展开状态按页面保存，重进后恢复，并有清除筛选入口。
- 结果支持上回合完赛与距离／场地筛选。
- 常驻且可点击的回到顶部按钮，不能遮挡主要操作。
- 长列表分批加载或虚拟显示；比赛与殿堂候选可默认前十并展示更多。
- 详情弹窗的多个工具按钮需在小屏可访问，不挤出屏幕。
- 马匹称号区域展示G1数、主／子年度奖项、系列赛、世界马王等结构化荣誉。
- 奖项候选有足够空间显示得票率与代表战绩。
- 隐藏能力规则适用于详情、筛选、排序、表格导出和提示，不只作用于主页。

参考的“删除某次比赛记录”“清算远古”“清算未办”应区分：

- 从结果页面隐藏：保留事实、生涯、奖金、评分与荣誉，不会显著减少底层存档体积。
- 历史归档：减少常驻内存与常用查询范围，不删除成绩。
- 真正删除：可能影响关联与统计，需要单独定义，不能伪装成列表清理。

## 18. 自建马与赛事表格导入导出

### 18.1 目标与格式

玩家可以在本地编辑表格，快速批量新增／修改内容，并分享马匹、家系或赛事包。

- Excel（.xlsx）：推荐完整模板，允许多个工作表组织关联设置。
- CSV：简单平面数据导入导出，明确UTF-8编码、列名、单位、空值语义。
- 创作模板与完整存档分开：前者包含定义，后者包含时间、比赛历史、评级与进度。

入口：下载空白模板、导出所选、导出全部、导入文件。模板附说明、允许值与示例。

### 18.2 模板内容

| 模板 | 主要字段 |
| --- | --- |
| 自建马 | 稳定编号、名字、年龄／出生年、性别、毛色、基础能力、现有适应性、距离、巅峰期、马主、父母 |
| 赛事 | 稳定编号、名字、格付、马场、地区、场地、距离、月份、上／下半月、年龄／性别条件、各名次奖金 |
| 关联表 | 马场／马会／马主、系列赛、特殊参赛条件、可选负重与标准造时等 |

名称允许重复与修改，不靠名称作为唯一关联键。导出自建马的完整创作参数，普通AI马导出范围必须遵守隐藏信息边界。

### 18.3 导入行为

- 新增副本：生成新身份，可作为默认方式。
- 更新已有：按稳定编号匹配，预览字段变化。
- 跳过已有：便于重复导入分享包。
- 更新时空白默认保持原值；清空用明确语义，不能因漏列误删数据。
- 缺失的马场／马主／父母可以匹配现有或一并创建；完整分析关联后再导入，不依赖行顺序。
- 未提供高级设置使用明确默认，不接受无提示的任意推断。
- 历史结果不因更新创作参数回写。

### 18.4 校验与预览

- 显示新增／更新／跳过条数。
- 错误精确到工作表、行、列；例如月份13、距离下限高于上限。
- 检查重复编号、关联缺失、年龄和巅峰区间、父母循环、日期、奖金额与比例。
- 检查公式单元格、空白、数字文本、小数、中文标点等常见输入，采用明确支持策略。
- 应用时保证一致提交，失败不留下半批内容。
- 允许重复导入同一模板而不无意复制赛事；提供冲突处理选择。

### 18.5 分享与兼容

- 单场赛事可导入到接收方现有马场。
- 完整赛事包可携带马场与系列赛。
- 马匹家族包可携带必要祖先，不能把外部ID误关联到本地同编号对象。
- 导出后重新导入，应保留全部受支持设置。
- 模板有格式版本，未来新增字段兼容旧模板；不能把未知新版字段静默误解。
- 跨存档导入比赛不修改源存档；“统一归入第一个马场”是参考选项，应让目标明确并保留地区语义。

## 19. 大型存档与性能目标

### 19.1 当前问题

现有模式保存整个生涯为JSON再写localStorage。新模式马群、几十年赛史、家谱与投票规模更大，反复序列化会增加保存开销。

现有结果中也存在同一组排序结果被多个字段引用的情况，JSON会重复展开。新模式不能给每匹马复制整场完整结果。

### 19.2 推荐存储架构

- IndexedDB保存世界实体、出赛记录、评级、奖项、年度档案与存档信息。
- localStorage只保留少量轻量偏好或入口信息。
- 每个对象保存一份，用稳定ID关联；只为历史正确性保存必要条件快照。
- 每场一份届次记录，加每匹马一份出赛成绩；马匹／骑手／赛事页面查询同一来源。
- 血统保存父母ID，展开时读取祖先，不递归复制整份家谱。
- 当前马群与近期赛事常用数据在内存，历史按页、年份、条件读取。
- 统计在事件发生时增量更新，可从基础事实重建，不每次页面切换扫描全部历史。
- 索引围绕世界／存档、年份、马匹、赛事、归属与常用排行建立。

### 19.3 保存一致性

- 每半月保存本回合新增结果、变动状态、统计与时间，作为一个完整提交边界。
- 计算先完成，再提交相关数据；失败保留上一完整状态，不能赛果存在而奖金未到账。
- 明确已结算标记、随机状态／已生成结果，恢复后不重抽同一场或重复发奖。
- 改分、编辑赛事和颁奖草稿及时保存对应记录，不依赖关闭网页。
- 多存档槽与恢复点不能共享可变记录后相互污染。
- 存档格式版本、迁移、导入校验和失败恢复从第一版设计。
- 读取失败保留原始数据，不沿用普通模式部分路径中失败即清除的行为。

### 19.4 玩家存档功能

- 至少保留原设想的10个手动存档槽。
- 最近若干回合与年末自动恢复点，保留数量待定。
- 完整存档文件导入导出，可考虑压缩与后台处理。
- 显示存档年份、马匹数量、保存时间、容量与保存状态。
- 重置当前世界不删除其他存档。
- 浏览器容量仍有限；可请求持久化并检测容量，但不能承诺永久不丢失或无限容量。提供独立文件备份。

### 19.5 性能策略与验证

- 批量生成和快进分批执行，必要时后台处理，进度可见且可取消。
- 页面分页／虚拟列表，避免一次渲染上万条。
- 默认只加载当前视图需要的数据。
- 仅换成IndexedDB而继续整世界读写，不算完成存档优化。
- 无人为数量上限不意味着承诺无限设备容量；实际支持规模用性能测试给出。
- 重点测连续多年、大量马匹与出赛记录、家谱展开、排行榜、导出导入及中断恢复。

## 20. 建议实施阶段与验收

### 阶段一：世界与存档基础

建立模式隔离、世界时间、真实马匹身份、赛事定义与届次、基础马场、结构化存档、完整保存恢复。确立半月结算、历史快照与随机结果不重复生成。

### 阶段二：可旁观的完整赛季

接入原引擎的多马模拟、AI排赛、骑手分配、普通赛与重赏、轻度G1压力、取消60保底、完整名次、半月汇总与重大G1展示。

### 阶段三：主席评价与创作

机器评级校准、手动WTR、年末奖项、基础殿堂、搜索筛选、马匹／比赛编辑及Excel／CSV导入导出。导入导出属于首个完整可用版本的范围，不长期后置。

### 阶段四：长期传承

自动出生与出道、真实父母及血统继承、种马与后代观察、马主与马会偏好、系列赛和长期纪录。

自动繁殖是目标核心之一；即使按阶段开发，完整版本应包含基础自动换代，而非只依靠手动补马。

### 后续扩展

复杂负重、细化造时、完整主子荣誉、议会投票、百大逐轮选举及更多世界政策。根据实际观察体验决定投入，不以功能数量替代核心质量。

### 首个完整版本验收场景

1. 创建／导入一个赛事世界后，无需逐匹操作即可连续运行至少五个游戏年。
2. 马群合理出赛、休整、退役与补充，重要比赛有稳定参赛来源。
3. 玩家只处理半月汇总和年末，也能完成体验；不评分时机器接管默认流程。
4. 隐藏能力不会被普通筛选、提示或导出泄露。
5. 自创马遵守同一引擎，后代可追踪且年代关系合理。
6. 修改赛事、转会、改名不重写历史。
7. 保存读取不重抽比赛、不重复颁奖，恢复点可独立回退。
8. 自建马／赛事表格往返导入导出不丢设置，关联对象与冲突处理清楚。
9. 大马群下强弱关系仍可识别，偶发失常与退赛的频率经验证。
10. 旧模式与原存档行为不因主席模式配置而改变。

## 21. 首轮之后仍需明确的事项

首轮已定稿的评分、马群规模、半月节奏、取消规则、参赛上限、恢复点数量及延后范围见文首状态表，不再作为开工阻塞项。

- TF尺度与压力参数的试玩校准；是否进一步加入经验，而不使强马过于稳定。
- 自动繁殖的年代、繁殖资格、亲缘限制、遗传强度及后代观察。
- 强制参赛超额、健康限制与无视参赛条件的边界。
- 世界马王、系列赛、称号、主子马会奖项与殿堂的统计口径。
- 百大特批、议会投票分母、并列、延续失效、重投与门槛比较方式。
- 负重、造时如何接入引擎及校准；不在首轮叠加参考公式。
- Excel多工作表模板及未来数据／规则版本迁移；进一步评估低性能移动设备。
