# 赛场适性判定与日本赛程基线

更新时间：2026-09-22
状态：第二阶段进行中。本文件记录当前统一判定口径、已确认的日本中央 G1 基线和待分类处理方式。

## 判定口径

赛程身份固定为“赛马场＋表面＋距离＋具体路线”。分类描述的是正常场地、正常 G1 级别阵容和正常比赛节奏下，该路线长期稳定的比赛性质；单届比赛的大逃、极端慢步速或异常天气不改变档案。

每条赛程只保存一种类型与一个等级。判定顺序固定如下：

```text
前半程是否天然容易长期处于较高压力？
├─ 是：消耗
└─ 否：是否通常在终点前约 700～1200m 就开始持续提速？
       ├─ 是：持久
       └─ 否：瞬发
```

- **消耗**：较早开始消耗能力储备，缺少明显蓄力阶段。距离长、坡多、欧洲草地或重场不能单独作为依据。
- **持久**：通常在终点前约 700～1200m 或更早进入持续高速竞争。核心是冲刺过程长，不是比赛距离长。
- **瞬发**：胜负通常保留到最后约 400～600m，短时间加速和末脚竞争更关键。长直线不能单独作为依据。
- **Ⅰ级**：有稳定倾向，但阵容、骑法或节奏较容易改变其表现。
- **Ⅱ级**：赛道结构强烈促使该比赛形态，通常会明显挑选对应适性。

难以明确时，只选三类中最接近的一类并优先使用Ⅰ级。不得增加混合类型、第四种类型或额外马匹属性。地区、国家、表面、距离、直线长度或坡道均只能作为综合判断资料，不能单独完成分类。

## 数据约定

共享档案定义在 [race-course-profiles.js](../js/data/race-course-profiles.js)。每条档案至少包含：

```js
{
  id: "jp-tokyo-turf-2400-standard",
  trackId: "tokyo",
  courseConfigId: "jp:tokyo:turf:2400:standard",
  routeId: "standard",
  surface: "草地",
  distance: 2400,
  type: "burst",
  intensity: 1,
  status: "confirmed",
  confidence: "confirmed"
}
```

赛事仅保存 `courseProfileId` 与路线字段，不复制类型或等级。未确认赛事没有默认档案，也不会从旧 `course`、地区、表面或距离自动推断。主席世界会在解析本届实际举办地后保留匹配的档案引用；若改址或轮换到没有相同档案的路线，该届回到待判定。

这些字段目前只用于数据整理与审计，不会触发正式比赛能力修正。正式马匹属性接入属于第三阶段。

## 官方路线校验与初判档案

赛程档案库同时保存 JRA 十个中央马场的官方平地发走距离、内／外回或直线赛区分。资料来自 JRA 的 [东京](https://www.jra.go.jp/facilities/race/tokyo/course/)、[中山](https://www.jra.go.jp/facilities/race/nakayama/course/)、[京都](https://www.jra.go.jp/facilities/race/kyoto/course/)、[阪神](https://www.jra.go.jp/facilities/race/hanshin/course/)、[中京](https://www.jra.go.jp/facilities/race/chukyo/course/)、[福岛](https://www.jra.go.jp/facilities/race/fukushima/course/)、[新潟](https://www.jra.go.jp/facilities/race/niigata/course/)、[小仓](https://www.jra.go.jp/facilities/race/kokura/course/)、[札幌](https://www.jra.go.jp/facilities/race/sapporo/course/) 与 [函馆](https://www.jra.go.jp/facilities/race/hakodate/course/) 的赛道介绍。

官方目录能唯一确定路线的比赛可由共享解析器取得对应赛程档案。当前这些补充档案为 `provisional`／`low`：依据官方赛道结构与本文件的决策树做Ⅰ级初判，可逐条人工改为确认或改类型。它们不会覆盖上表的已确认 G1 模板。本阶段不在载入时改写原始比赛数据；第三阶段正式切换时才显式物化档案引用。

原有中央条件赛曾将通用距离池直接套进马场，出现如“东京草1000m”这类不存在的组合。现在由同一份官方目录在生成时保留原定距离，优先使用原马场、同举办组与同档期地方场；确实无法承办时才选择其他可承办的中央马场，并明确写入路线。这样条件赛不再把无效的真实马场名当作虚构赛程，也不需要在类型审计中例外放行。

若一个距离可同时跑内回和外回，而原始比赛数据没有路线字段，档案库会标记 `ambiguous`；若组合不在官方发走距离中，例如东京草1000，则标记 `invalid`。这两种情况均不自动选择赛程类型。

## 覆盖审计

运行 `npm run audit:course-profiles` 可重新遍历当前注册比赛库并输出机器可读报告；追加 `-- --write` 会在 [artifacts/track-aptitude-course-coverage.json](../artifacts/track-aptitude-course-coverage.json) 写入快照。

报告将比赛分为：

- `configured`：引用存在、且表面与距离通过校验的共享档案。
- `pending`：尚无人工确认路线，不推断、不临时套用Ⅰ级。
- `invalid`：赛事与所引用档案的表面或距离不一致，必须先修数据。

报告还会给出 `courseIdentity`：

- `resolved`：官方路线唯一、赛事明确写出内／外回，或当前阶段按 `standard` 合并内／外回，已可挂接。
- `ambiguous`：保留为将来需要更细路线粒度时使用；当前阶段不会因内／外回缺失阻塞接入。
- `invalid`：原始赛程并非该实际马场的官方平地距离。
- `unavailable`：当前资料只有国家或地区名，尚未给出实际马场和路线。
- `venue-resolved`：已有来源可确认实际举办马场，或原始资料只给出国家时已明确挂接到“巡回赛场模板”。系统会以赛场、表面、距离和标准路线生成低置信度Ⅰ级暂定档案；模板不会伪装为真实举办地，后续可直接替换。

当前快照已为全部 2170 场赛事挂接档案：1523 场为 `resolved`，包括全部 1336 场中央条件赛及 5 场按标准路线合并内／外回的命名赛事；647 场为 `venue-resolved`，其中包含实际赛场的低置信度Ⅰ级档案及明确标注的巡回赛场模板。`ambiguous`、`unavailable` 与 `invalid` 均为 0。后续每批赛程补录或重排后，必须重新生成报告；覆盖率不以本文件中的某个固定比赛总数作为验收条件。
