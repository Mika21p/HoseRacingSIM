# 剧情模式完善方案

起草日期：2026-10-13。状态：**2026-10-13 用户确认，进入 P1a**。2026-10-18 用户进一步确认收录、命名、沿革和结算原则，见第 8 节。
现状依据见 [剧情模式现状盘点-2026-10-13](剧情模式现状盘点-2026-10-13.md)。

## 1. 玩法定位

**一句话**：玩家扮演马主，带一匹马走进 1996–2000 年的日本赛马黄金年代。历史按史实发生；只有玩家亲自参加的比赛会改变结果，而这些改变会通过名声、报道和剧情向后延续。

已确认的前提（2026-10-13，用户答复）：

1. 每局只有一匹马，可以重复游玩，每次从不同类型的马里选择。
2. 只有玩家参加的比赛会改写结果，但改写会产生连锁的叙事影响，例如赢下皋月赏和德比之后，会成为备受期待的三冠候选。
3. 现有的 1997–1998 验证版可以废弃。
4. 正式文本由 Claude 撰写，用户审核。
5. **尽量全部真实**。这个模式相当于一部可以亲身参与的历史故事百科。除了玩家的马和玩家这一方的人员，赛事、出走表、马、人物、事件全部是真实的，并保留来源。
6. **剧情模式单独建立资料库**（真实出走表、马匹、人物、年表）；全局资料库中的部分内容可以复用。

体验目标：

- **群雄并起**：每个年份和路线都有真实的强敌、名将和名场面。玩家不参加的比赛，以史实新闻的形式呈现，让玩家始终感到身处那个时代。
- **参与感**：马主的决定（赛程、骑手、休养、远征、退役）和比赛结果，会改变名声、媒体态度、对手关系和后续剧情。
- **重玩价值**：不同类型的马对应不同年份、路线和对手，同一年份也会因为结果不同而走出不同的世界线。

不追求的方向：完整模拟其他马的生涯；按日期写死、穷举所有分支的剧本树。

## 2. 核心设计：三层结构

| 层 | 负责内容 | 生产方式 |
| --- | --- | --- |
| **历史世界（独立资料库）** | 1996–2000 年的年代赛历、史实结果（G1 和主要前哨赛收前 5 名，其他比赛只收冠军）、马匹和人物资料、年表事件、史实新闻 | 数据录入和抓取解析，逐条附来源；详见第 2.0 节 |
| **系统叙事** | 从事件流推导叙事标签（三冠候选、宿敌、连胜、伤后复出、名声等级等），再用模板生成新闻和赛前报道 | 模板加槽位，一个模板覆盖大量组合 |
| **手写剧情** | 剧情片段（storylet）：触发条件、优先级、文本、效果；每年少量“名场面” | 手写，草稿后由用户审核 |

### 2.0 剧情模式资料库（年鉴）

独立于全局史实马库（全局库只记胜鞍，不记出走表），由本线维护，存放在 `js/data/era/almanac/`。

| 资料 | 内容 | 来源 |
| --- | --- | --- |
| 赛事回 | 某年某场比赛的当年名称、等级、日期、场地、距离、天气、马场状态、出走头数。出走马分两档收录（用户 2026-10-13 确定）：**G1 和主要前哨赛收前 5 名**；**其他比赛只收史实冠军**，另有重要出走马时可以单独补录。每匹收录马记着顺、马名、性龄、骑手、走时、着差、人气、练马师 | JBIS 赛果页（覆盖全部重赏）；G1 另用 JRA 历年结果页交叉核对（JRA 官网只保留 G1 的历年页） |
| 马 | 原名、中文名、英文名、性别、毛色、出生年、父母和母父、马主、练马师、产地（外国产马标记）、在本资料库中的出走记录（由赛事回反查）、退役和去向；名马另附百科条目 | 赛事回加 JBIS、JRA 等资料 |
| 人物 | 骑手、练马师、马主：正式汉字名、中文写法、所属、主要坐骑 | JRA、JBIS |
| 年表 | 规则变化（例如外国产马出走经典的限制、新设 G1）、重大事件（伤病、引退、转厩、海外远征、事故） | 官方资料与报道，逐条附来源 |
| 百科条目 | 名马、名场面、年度回顾的说明文字（Claude 撰写，用户审核） | 依据上述事实 |

**复用规则**：
- 马、骑手、赛事优先挂接全局 ID（`historicalHorseId`、`jockeyId`、`raceId`），并沿用用户已确认的中文名；
- 全局库没有的条目只在年鉴中登记，不写入全局库；
- 年鉴中出现的马要进入全局史实马库（其他模式使用）时，由 C 线按 `.agents/skills/keiba-historical-data/` 的规则录入，本线只提供清单；
- 骑手在年鉴中以真实姓名出现即可，不要求全部进入全局骑手库。

**抓取与校对**：
- 在 `scripts/` 增加只读抓取和解析工具，原始页面缓存到主目录 `artifacts/` 下按日期命名的子目录；
- 解析结果写成年鉴数据文件，每条带来源 URL；
- 抽样人工核对后才入库；
- 只保存事实数据（名次、走时等），不转载报道原文。

**百科浏览**：模式内提供年鉴界面（年度、赛事、马、人物、年表）。玩家亲历的比赛和改写的世界线会在条目里标注，例如“史实：特别周胜出 / 本局：XX 胜出”。是否随游戏进度逐步解锁，待确认。

### 2.1 历史世界与世界线

- **年代赛历**：为每年列出可以参加的比赛（引用年鉴中的赛事回，按当年真实的等级、日期、场地、距离）。比赛的出现与否只由赛历和参赛资格决定，**不再需要“决策节点”来开放报名**。盘点中的缺陷 D1 属于这类死路，在这个结构下不会出现。
- **按比赛表现分插入**（2026-10-18 确认，替代早期“按走时插入”设想）：收录马的相对顺序保持史实，玩家由模拟器计算本场表现分，决定插入位置。史实走时和官方着差作为资料展示，不直接充当跨比赛通用能力尺度，也不据十分之一秒的走时反推鼻差、头差。
  - **前 5 名档**：玩家与收录马比较本场表现分；落在第 5 名之后时，未收录部分的具体名次属于模拟估算，不伪装成史实。
  - **冠军档**：与史实冠军的本场表现分比较，其他未收录马不具名；具体名次与着差由模拟结算。
  - **史实与模拟分开**：年鉴保留原始结果，本局单独记录模拟名次、着差和叙事影响，不覆盖史实走时。表现分需按场次校准，不机械换算真实走时。
  - 条件赛的收录范围、表现分标定、同分处理与未收录部分估算，在 P1b 细化并测试；此前“不收任何条件赛史实结果”的设想不视为用户确认的排除规则。
  - 出走头数照搬史实，**玩家顶替一匹未收录的马**，总头数不变（用户 2026-10-13 确定）。被顶替的马不具名，也不影响任何收录马的史实结果。如果某场比赛收录了全部出走马（极少数头数很少的比赛），就没有可以顶替的马，这种情况在 P1b 实现时单独处理。
- **世界线记录**：记录玩家改写过的比赛（谁本该赢、实际谁赢、玩家名次）。后续新闻、剧情和对手描述会查询这份记录。例如玩家赢下德比之后，特别周在后面的报道里会被称作“德比亚军”。**其他马后来的比赛结果不重新推演**；只有当玩家也在场时，结果才会被改写。
- 盘点中的缺陷 D3（生成场次的胜者被误记）由“世界线只记录实际出现在出走表里的马”这一规则消除。

### 2.2 叙事标签（连锁影响的载体）

从不可变的事件流推导出一组标签，存档中只保存事件，标签可以随时重新计算：

- 成绩类：`unbeaten`、`two-crowns`、`triple-crown-candidate`、`crown-lost`、`g1-winner`、`slump`
- 关系类：`rival:<马ID>`（同场 2 次以上并互有胜负）、`nemesis:<马ID>`（多次输给同一匹马）、`jockey-bond`
- 状态类：`injury-return`、`overseas`、`retired`
- **名声**（0–100）：由胜场等级、改写史实的次数、连胜和人气推导，影响报道口吻、骑手邀约和剧情可选项。

叙事标签是剧情片段条件和新闻模板槽位的唯一输入，规则代码里不再写死赛事 ID。

### 2.3 剧情片段（storylet）

```js
{
  id: "jp.1998.derby-eve.crown-hope",
  when: { window: ["1998-05-16", "1998-06-01"], tags: ["two-crowns"], entered: "tokyo-yushun@1998" },
  priority: 60,
  once: true,
  speakerId: "press-keiba-weekly",
  textId: "jp.era.1998.storylet.derby-eve.crown-hope",
  choices: [/* 可选；每个选项可以设置效果 */],
  effects: [{ type: "fame", delta: 3 }, { type: "tag", add: "media-spotlight" }]
}
```

- **条件**：一个受限的声明式条件格式（时间窗口、标签、名声区间、是否报名或参加某场、世界线是否改写某场、马的类型等），**不使用 eval**。
- **效果**：只允许白名单内的效果：名声、标签、关系、开放选项、骑手邀约，以及少数“世界线事件”（例如对手阵营更换骑手，仅用于叙事）。
- 选择逻辑：每回合挑出条件满足的片段，按优先级取一到两个，避免刷屏。“名场面”可以设为高优先级并强制显示。
- 加剧情就是加片段，不需要改规则，也不需要排节点日期。

### 2.4 新闻

- **史实新闻**：玩家没参加的重大赛事，各有一条简短史实报道（来源可查）。
- **改写新闻**：玩家参加的比赛按结果（胜、惜败、大败、爆冷、改写史实）选择模板，并填入对手、着差、人气、叙事标签等槽位。
- **专题和评论**：由叙事标签触发，例如三冠候选特辑、宿敌对决预告、伤后复出追踪。
- 现有的报纸箱界面继续沿用，新闻只进报纸箱，不打断主流程；只有剧情片段会进入主流程。

### 2.5 马主的决定

| 首个可玩版本 | 后续版本 |
| --- | --- |
| 自由赛程（按年代赛历和资格）、休养、主动退役 | 海外远征（1998–1999 年欧洲路线） |
| 骑手：初期由虚构骑手策骑；名声达到一定程度后出现史实名骑的邀约，同场已有史实坐骑的骑手不能接受 | 换练马师、转厩 |
| 赛前访谈或表态，由剧情片段提供选项，影响名声和媒体口吻 | 退役后的种马或繁殖结语（可衔接血统系统，需与 E 线协商） |

### 2.6 马的类型与入场世代

每种类型决定出生年份（世代）、路线和对手，属于数据而不是代码。首批建议 4 种：

| 类型 | 建议世代（三岁年） | 主线 | 特色 |
| --- | --- | --- | --- |
| 王道型牡马 | 1998（黄金世代） | 三冠到古马王道 | 特别周、青云天空、帝王光环 |
| 牝马 | 1996 或 1997 | 樱花赏、优骏牝马、秋华赏（1996 年新设） | 气槽、目白多伯 |
| 英里/短途型 | 1997 或 1998 | NHK 英里杯、安田纪念、英里冠军赛、短途锦标 | 大树快车 |
| 外国产马 | 1998 | 当时不能出走经典赛，改走 NHK 英里杯、日本杯和海外远征 | 神鹰、草上飞的时代背景 |

外国产马不能出走经典赛等年代规则都写进数据，并在录入前逐条核实。

### 2.7 结局

不再设固定的 6 种结局，改成**生涯评价加年代纪事**：

- 退役时，按胜鞍、改写的史实、名声和关系标签挑出一段结语片段；
- 再生成一张“那个年代”的纪事版面，把玩家马和真实名马的结果并列排出。

可以另行设计称号，例如“改写三冠的马”或“青云天空最难缠的对手”。剧情马是否进入殿堂和成就，需要与相关线协商（`hall-of-fame.js` 和 `app.js` 中的殿堂入口不属于本线）。

### 3.1 参赛资格（简化版）

按条件阶段晋升：新马 → 未胜利 → 1 胜级 → 开放级 → 重赏。G1 采用简化的“收得赏金或重赏成绩”门槛，经典赛加上性别和产地限制。数值阈值在第一阶段确定后写入方案，用于取代现在“剧情节点开放即可报名”的做法。

## 4. 文本分工与流程

- **撰写**：Claude 写草稿，状态为 `draft`。涉及史实的句子在旁边注明来源链接，或标为待核实。
- **审核**：用户审核通过后改为 `final`。修改意见直接作用于对应的文本 ID。
- **界面**：`draft` 可以照常显示，但开发构建中会加一个小标记；`outline` 和 `placeholder` 都不能被触发（校验会拦截）。
- **送审格式**：每批交一份按 ID 排列的审核清单（Markdown），列出 ID、触发条件和正文，方便逐条批注。
- **史实边界**：真实人物（骑手、练马师）的对白避免虚构其私下言论，以赛后公开表态的口吻为主；涉及事故和死亡（例如 1998 年天皇赏秋）时克制处理，并先与用户确认写法。

## 5. 存档兼容

- 新剧本采用 `RUN_VERSION = 6`，`localStorage` key 沿用 `keiba-era-save-v1`。
- 旧的 v1–v5 存档属于已废弃的验证版，**不迁移**。读档时识别出旧版本后：
  1. 把原始数据原样备份到 `keiba-era-save-legacy`，只保留一份；
  2. 明确提示“验证版剧情存档已归档，新剧本需要重新开始”；
  3. 不再静默删除。
- 修复读档机制：版本判断改为显式区间加逐版迁移表；`normalizeSave` 出错时先备份再提示，不直接 `removeItem`。
- 存档只保存事件流、决定和必要的快照；叙事标签和名声可以重新计算，减少以后迁移的负担。
- 剧情模式专用随机种子保存在存档里，用于复现和自动测试。

## 6. 验收标准

**每个阶段都要满足**：

- 运行 `npm test` 和 `npm run build:web`；
- 新增剧情模式专项测试；
- 浏览器检查桌面宽度、手机宽度（375px）和控制台无报错。

**自动通关工具**（固定种子，使用真实模拟器，放在 `scripts/`；新增 npm script 时会在交接时说明）：

- 每种马的类型 × 若干种子 × 几种策略（随机、直奔重赏、保守）：不卡死，没有永远报不上的目标赛；
- 报告结局和评价分布、各重赏胜率、剧情片段触发率（标出从未触发的片段）、文本状态统计。

**规则正确性**：
