# 主席模式：评议会、殿堂与地方年度奖项

> 2026-09-21：中央殿堂已改为综合评分择优，详见[殿堂投票优化与验收](殿堂投票优化与验收.md)。本文的独立抽票、百分位权重及原有爱好乘数描述适用于年度奖与旧版殿堂记录。

实施日期：2026-09-20。依据已批准的《本轮开发方案：自定义评议会、殿堂评选与地方年度奖项》。本轮仅在本地构建，不发布线上。

## 使用入口

1. 打开主席世界的 **殿堂 → 评议会**，选择中央或某个地方马会，创建理事类型。所有评议会初始为空。
2. 填写名称、人数、票权、代表地区；评价倾向合计100%。六类距离与草泥地爱好分别设为−100～100，默认0，可以一键归零。
3. 继续赛季。最后一个半月完成后，已配置的评议会自动生成年度建议；中央理事另外表决殿堂。没有理事也能照常推进。
4. 在 **年度奖项** 切换中央／地方，查看投票、类型分票及逐人依据。可只填空缺，或查看差异后覆盖草稿；并列最高由主席选择。只有年末封存才颁发年度奖。
5. 在 **殿堂 → 候选** 查看候选，核准达到门槛者或主席特批。默认60%，默认需要核准；“入选规则”中可开启自动授予。
6. **评选记录** 可查看冻结的投票轮次，以及殿堂授予、评语和撤销误授记录。每匹候选保留最近一次支持率，跨年继续显示。

马匹统一档案的“荣誉”页分别显示中央／地方年度奖和殿堂身份；马匹页“更多筛选”可分别筛选中央奖、地方奖、中央殿堂。各列表沿用名字跳转、分页和筛选保存。

## 落地规则

| 项目 | 实现 |
| --- | --- |
| 理事身份 | 每个成员独立编号、独立抽票；类型支持编辑、复制至任意评议会、停用、删除。缩减后重新增加的人不会继承旧成员历史；历史轮次保留配置快照。 |
| 评价依据 | 年度与生涯分开。优先已核准WTR，完全没有时采用TF−5；0分有效。旧制自动WTR不作为人工评价。 |
| 评价倾向 | G1、评价、奖金、胜率、荣誉、地方、延续、随机、弃权。数值指标用并列中位百分位加权；G1或奖金全为0时对应倾向弃权。年度投票排除荣誉后归一。 |
| 爱好依据 | 只读公开完赛事实，含后台OP及隐藏赛果；格付8／4／2／1，名次3／2／1，退赛不计。距离和场地分别汇总，再用 `2^((D+S)/100)` 修正抽选权重。 |
| 延续 | 只读上一年度同项目最后有效轮次的个人支持。失效则排除延续重新抽倾向；本年重投不会成为“去年”。 |
| 年度奖 | 每人一票或弃权。包含弃权的全部票权作分母；建议不擅自覆盖人工草稿，年度结束时封存。 |
| 殿堂投票 | 每人最多支持3匹、不重复，同一匹每次支持计完整票权。各马支持率相加可超过100%。零总票权不会通过。使用百分之一票权整数和精确交叉比较判门槛。 |
| 殿堂资格 | 已实际参赛的退役马，且有G1、中央年度奖或生涯评价≥120之一。可特批提名、暂时排除／恢复；基础祖先及未参赛繁殖资料不自动入池。 |
| 地方奖 | 每个稳定地区对应独立可改名的马会，默认启用12奖、宽松候选。年度归属年初冻结，远征不改变资格；转属次年生效。地方奖不冒充中央奖或中央殿堂初筛条件。 |
| 历史 | 冻结名字、配置、指标、候选和逐人选票。改分只影响未来依据；主动重投新增轮次。撤销误授保留修订，不删除原始授予。 |

普通马隐藏能力、精确适性、巅峰期和配种实力不进入候选投影或选票。投票不使用比赛、AI、繁殖随机流，也不修改这些规则。

## 数据与恢复

- 数据库升级至v6，完整存档版本为v5，支持读取完整格式v1～v4。升级前建立“规则升级前”恢复点；评分旧制和荣誉初始化需要同时迁移时在一次提交中完成。
- 新增理事类型、公开荣誉摘要、投票轮次、逐人选票、殿堂授予修订、年度封存记录。历史按世界及年度、范围或轮次查询，每页最多50条。
- 老奖项按中央奖理解；只从已有赛绩／评级／奖项建立公开摘要，不补造旧投票、地方奖和殿堂身份。
- 投票使用独立、持久化随机源。每100位理事让出一次界面处理机会；提交前可取消。完整结果、随机状态、自动入选记录一次事务提交，失败不留下半轮结果。
- 手动槽、回合／年末恢复点、完整导入导出和单页面写入锁继续适用。删除当前理事配置不删除过去的个人选票。

## 验证与复现

验收结果：162项常规测试、6项长期测试、生产构建及桌面／手机实测通过。五组20年荣誉模拟合计4,900轮评议、82,200份逐人选票；没有重复授奖或身份关联失败。

常规验证入口：`npm test`。本轮共162项（原152项＋9项荣誉规则／存储测试＋1项实际界面交互测试）。覆盖：

- 倾向比例、票权、身份扩缩、爱好方向与隐藏属性隔离；3000位理事固定输入比较。
- 三票不重复、弃权分母、零票权、门槛精度、延续、重投、提名／排除、撤销。
- WTR为0、TF后备、年度归属、地方与中央荣誉分离、跨年支持率。
- 事务中断与重试、旧格式迁移前恢复点、历史身份、恢复和重新导入。
- 实际挂载界面点击保存理事、滑杆、殿堂核准、逐人选票、授予记录、地方奖评语自动保存、荣誉筛选及推进后保留。

长期验证入口：

| 检查 | 数据规模 |
| --- | --- |
| `npm run test:honors:long` | 5个固定种子各20年；每世界980轮评议、16,440份逐人选票；含年度建议采用、地方授奖、殿堂自动授予、重复防护与年末转换。 |
| `npm run test:chairman:long` | 默认世界5年；另构造1000匹现役马、20年历史，检验保存、分页、恢复与导出。 |
| `npm run test:breeding:long` | 5个种子各20年；另外执行真实30代循环及多种子、不同配种实力分布试验。 |

真实浏览器使用本机Chrome的独立测试上下文，页面为本地生产构建，不触及玩家世界。脚本为 `scripts/check-chairman-honors-browser.js`（需要可用Playwright及Chrome；`--large`启用规模验证）。检查1440×900和390×844，包含实际点击、保存、刷新、移动端溢出和固定保存按钮位置。

规模场景：10,000匹历史马、1,000位理事、20年殿堂轮次、20,000份逐人选票；检验最后一页查询、完整世界载入、分批计算、取消后保存随机状态不变。投票是长操作，有进度和取消；这不等同于每轮投票必须在一秒内完成。最终测量及五组模拟计数收录于 [本轮验证数据](主席模式荣誉验证数据.json)，时耗为本机观测值。

本机最终观测：末页50份选票查询19ms，20年轮次列表查询464ms，完整世界载入237ms；20轮大型表决与保存合计约94秒，产生200次分批进度。手机页面无整体横向溢出，固定保存按钮底部位于835px（视口高844px）。长操作可点击“停止当前操作”，取消测试确认未修改保存中的评议随机状态。

## 本轮边界

没有新增正式殿堂排名、百大、地方殿堂、完整主子马会经营。默认理事为空，玩家需自行创建；未核准或未处理的投票不会阻挡年末，也不会擅自颁发年度奖。已有比赛、AI排赛、TF／WTR与繁殖机制继续使用原规则。
