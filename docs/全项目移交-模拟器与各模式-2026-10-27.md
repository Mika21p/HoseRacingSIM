# 全项目移交：模拟器与各模式

整理日期：2026-10-27。本文件是基于当前剧情工作区源码的结构导航，不是完整代码审计。行号是本次只读核对时的定位，源码变动后须重新搜索。

## 1. 页面加载与模块总图

入口是 [index.html](../index.html)。页面按顺序加载原生 JavaScript/CSS，不使用前端框架和模块打包：

1. 随机工具、血统、骑手、赛事注册表/各地区赛事、赛道目录与帮助。
2. 更新日志、首页模式文案、史实马索引。
3. 剧情年鉴 registry、1998/1999 horses/races/entries、剧情 registry/texts、calendar、race performances、storylets、news 和 scenario。
4. 通用规则：地区、时间、赛程、出道、成熟度、性格、骑手、伤病、疲劳、赛场适性、马匹生成、血统、历史对手、比赛模拟器。
5. 剧情规则和 UI，再加载主席规则、Worker、存储、UI，最后 [js/app.js](../js/app.js) 启动应用。

所有模块通过 `window.Keiba` 命名空间注册；**加载顺序是隐式依赖**。移动、重命名或改成 ES module 前必须先验证全页面和测试加载器。

首页模式文案在 [js/data/home-modes.js](../js/data/home-modes.js)，当前五个 ID：`career`、`legend`、`rogue`、`era`、`chairman`。普通/传奇/肉鸽/剧情入口主要由 `js/ui/render.js` 和 `js/app.js` 处理；主席卡和大厅由 `js/chairman-app.js` 动态追加。殿堂是跨模式入口与服务，不另算第六种模式。

## 2. 底层赛马模拟器

源码：[js/rules/race-simulator.js](../js/rules/race-simulator.js)。当前剧情工作区的 `ns.RaceRules` 主要包括：

- `simulateRace(horse, race, options)`：普通单马/传奇/肉鸽使用的比赛入口。
- `simulateWorldRace(runners, race, options)`：主席模式全场世界赛事入口。
- `simulateEraFieldRace(horse, race, options)`：剧情历史全场入口。
- `chooseOpponent`、`chooseOpponentField`、传奇候选筛选、对手生成、年份标准化以及场地、距离、取位等辅助函数。

### 2.1 `simulateRace`

输入包含玩家马、赛事和 `options` 上下文。`buildRaceContext`会读取对手、场况、玩家骑手、当前时间、成熟度/衰退、性格修正和赛前状态，并经 `HorseRules.calcRaceAbility` 计算能力。普通决斗与全场路线根据赛事级别、对手数等分流；公开赛、Listed 和重赏通常进入 field。

输出为 `{ public, hidden }`：

- `public` 面向 UI：比赛名、名次、对手、退赛/受伤等。
- `hidden` 面向规则、评论和调试：能力计算、分数、差距、阶段结果与全场细节。
- 普通全场超过展示前五名的实际名次在 `hidden`，`public` 中可能为 `null`；修改展示逻辑不能把它误当成模拟器没有名次。

普通生涯和肉鸽的实际调用在 `js/app.js` 的比赛推进路径。传奇在报名阶段锁定五匹史实名马；候选不足应报错，不能静默补随机马。

### 2.2 `simulateWorldRace`

主席 `js/rules/chairman.js` 将各参赛者的 horse、时间、衰退、condition、jockey 组合传入；模拟结果含 `trackCondition` 与各马 `horseId/rank/retired/injury/total/margin` 等，必要时附能力计算。主席结果随后用于 TF/评分和年度统计。

这是世界赛/多马的世界计算入口，不等同于普通玩家 UI 的 `simulateRace`。改动要考虑主线程、Worker、排赛、评分、存档和长期人口场景。

### 2.3 `simulateEraFieldRace`

剧情入口由 `js/rules/era.js` 调用，`js/rules/era-world.js` 依据年鉴和表现值构造固定史实名、匿名补位、`headcount` 和历史场况。输入严格检查：总头数 2–32、`opponents.length === headcount - 1`、ID 唯一、不与玩家冲突、对手 `historicalScore` 有效。

剧情路径的特殊约定：

- 固定历史分、真实阵容规模、完整排名和 `eraField/headcount/fieldSize` 返回字段。
- 玩家随机参赛；固定史实马保持同着组，玩家同分时排在该组后；匿名对手分数低于实名估算。
- 未参赛的史实赛事不调用玩家模拟，而是从历史表现写入 `worldResults`。
- 这套完整头数和历史排序只属于剧情入口；不要因共享 `race-simulator.js` 就把剧情规则套到普通生涯或主席世界。

### 2.4 随机、可复现与副作用

随机工具是 `js/utils/random.js`：默认 `Math.random()`，也支持 `withSource` 临时替换和 seeded state。剧情 `randomAction` 会以 `run.rngState` 包裹候选与推进，成功后更新状态；普通报名部分仍直接使用 `Math.random()`，所以不能声称全应用行为都可由同一随机状态复现。

注意两个修改风险：

- `Random.withSource` 是同步的全局临时源，不能跨异步边界使用。
- 剧情的匿名分估算会给传入的 opponent 写入 `estimatedScore`；如果调用方复用输入对象，需要防止意外状态污染。

比赛公共结果、隐藏结果和调用方依赖是数据契约；改字段前先搜索所有消费者及测试，不要只改生成端。

## 3. 各模式边界

### 3.1 普通生涯（career）

- 入口：`app.js` 的模式选择和通用出道设置。
- 规则：`js/rules/career.js`、`career-bloodline.js`、`time.js`、`race-progression.js`、`race-fatigue.js` 等。
- UI：`js/ui/render.js`、`js/ui/race-selection.js`、`app.js` 的推进和结算。
- 存档：`localStorage` 的 `keiba-career-save-v1`。
- 共享：通用选赛、报名、模拟器、骑手/适性/疲劳和血统能力。普通规则修改会波及传奇与肉鸽，先看 `gameMode` 分支与测试。

### 3.2 传奇（legend）

- 与普通生涯共享设置、选赛和生涯推进，但报名时约束史实对手池，并不等于普通模式随机对手。
- 传奇候选受区域、场地、距离、性别、年份和强度约束；不足时应显式失败。
- 使用普通生涯存档模型，读取时必须保留 `gameMode` 分流；修改普通存档键或加载行为要同时检查传奇继续入口。

### 3.3 肉鸽（roguelike）

- 入口：`app.js` 的商店、候选、设置、骑手、结算和继续流程。
- 规则：`js/rules/roguelike.js`，比赛阶段复用普通 `simulateRace`，但候选、荣誉币、解锁和 run 状态独立。
- 存档：独立 `keiba-roguelike-save-v1`，包含 profile/run；版本不匹配时现有逻辑可能删除旧存档，修改前必须明确破坏性影响。
- 血统/殿堂有显式接入点；不要把肉鸽收益或解锁状态混进普通生涯存档。
- 当前历史验收是轻量小样本，不代表长期经济平衡。

### 3.4 剧情/时代（era）

- 入口：`js/data/era/scenario-1998-main.js` 注册；`app.js` 进入 `era` hub，`era-render.js` 生成继续/开始/推进 UI。
- 规则：`era.js`、`era-world.js`、`era-conditions.js`、`era-storylets.js`、`era-news.js`、`era-narrative.js`、`era-save.js`。
- 数据：`js/data/era/almanac/`、`calendar/`、`race-performances/`、`storylets/`、`news/`、`texts/`；当前主要为 1998/1999。
- 存档：`keiba-era-save-v1`，当前 payload/run 版本由 `era-save.js` 管理；存在归档/禁止覆盖保护，不要照搬普通存档的失败删除策略。
- 目标设计是 1996–2000 黄金时代、单马重玩、玩家参赛结果改写并触发历史新闻/剧情连锁；当前落地范围明显小于目标，详见验收与遗留文档。
- `golden-road-1998.js` 等未在当前 `index.html` 加载的旧文件，不能当成当前 UI 已接入功能。

### 3.5 主席（chairman）

- 入口：`chairman-app.js` 动态挂载独立世界大厅。
- 规则：`js/rules/chairman.js`、`chairman-world.js`、`chairman-scheduling.js`、`chairman-ratings.js`、`chairman-breeding.js`、`chairman-genetics.js`、`chairman-honors.js` 等。
- UI/后台：`js/chairman-*-ui.js`、`js/chairman-worker.js`、`js/chairman-storage.js`。
- 存储：独立 IndexedDB `keiba-chairman-v1`（当前 schema 由源码核对），与 localStorage 生涯/剧情存档不同。
- 改动要同时关注排赛、人口、繁殖、评分、主线程/Worker 随机状态、存档兼容和长期场景。阶段12及后续年龄层修复的实际验收边界见 [验收与遗留](全项目移交-验收与遗留-2026-10-27.md)。

## 4. 跨模式基础设施

- 数据：`js/data/races/`、`jockeys.js`、`historical-horses/`、血统和赛道资料；新增资料要更新索引、实际计数和测试预期。
- 适性/疲劳/伤病/成熟度/性格：多个模式共享；小改公式也要看普通、传奇、肉鸽、剧情和主席调用边界。
- 殿堂：`js/rules/hall-of-fame.js` 与独立 IndexedDB `keiba-hall-of-fame-v1`，是跨模式服务，不是新的比赛模式。
- UI/主题：`css/`、`js/ui/`、主席专用 CSS/UI。界面改动必须检查桌面、手机与控制台。
- 构建：[scripts/build-web.js](../scripts/build-web.js) 将史实马逐文件源合并成带 hash 的发布包；`dist/` 不手工改、不提交。
- 测试：`tests/helpers/project-loader.js` 负责 Node 加载环境；`package.json` 的 `npm test` 指向 quick，长测另列。

## 5. 常见错误

- 把当前剧情未提交文件当成已在 main；或只移交 Git 提交而遗漏未跟踪剧情源码/测试/文档。
- 把 1998/1999 原型写成 1996–2000 全部完成。
- 把 `headcount`（本局模拟合同）和 `starterCount`（史实起跑数）混为一谈。
- 把历史报告的测试数字当成当前代码的新结果。
- 只改 `race-simulator.js` 但不更新普通/传奇/肉鸽/剧情/主席相关测试和调用方。
- 只跑 Node 测试就宣称史实准确、UI通过、长测平衡或线上发布成功。
- 为了通过测试而放宽赛事资格、虚构胜鞍/骑手或静默补随机对手。
