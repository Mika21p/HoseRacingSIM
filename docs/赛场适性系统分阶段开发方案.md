# 赛场适性系统分阶段开发方案

更新时间：2026-09-22

用途：供后续开发任务直接读取，保存已确认需求、开发顺序、阶段边界、验收标准与进度。

当前状态：**第一至五阶段已完成。** 赛程档案已覆盖全部比赛库；普通、肉鸽、剧情与主席模式均已使用新赛马适性字段和正式赛前计算。数值平衡验收将草泥G定为−20，其余初案保持；练马师六项评估、赛后新适性归因、基础认知记录与相关界面已完成，第六阶段已按用户要求完成单轮快速验证，发布准备待后续安排。

本文是本次规则重置的开发顺序依据，优先于《赛场适性系统审阅与第一阶段计划》中早期的阶段划分。原审阅文档保留代码调查与数值分析价值，但其中“第一阶段同步完成评语”等安排由本文替代。用户后续明确指示优先于本文。

## 一、总体判断与开发顺序

用户提出的顺序合理，采用以下六阶段：

1. 开发可独立试跑、后续可复用的核心机制实验版。
2. 遍历现有比赛库，建立共享赛程并更新比赛属性。
3. 接入正式赛马属性及各模式的数据入口。
4. 研究与调整现有规则的数值平衡。
5. 更新练马师评语与基础认知记录。
6. 整体验证，准备正式切换。

有三个贯穿约束：

- 第一阶段虽然早于正式马匹接入，仍须使用手工构造的实验马和少量样例赛程，否则无法验证计算。
- 赛程身份、马匹字段及比赛修正摘要在第一阶段确定；评语功能第五阶段实现，但其需要的输入不能到第五阶段才补设计。
- 每阶段完成针对性验证，最后阶段进行跨模块整体验证，不把所有测试拖到最后。第四阶段进行系统性平衡研究，第一阶段仍做基本数值检查。

开发中的实验入口与当前正式入口暂时分开；最终发布只维护新规则，不长期保留旧规则分支。不能把尚未适配完的正式入口直接接上新计算器并上线。

## 二、已确认需求与非目标

### 已确认

- 本次是规则基础重置，放弃旧存档兼容，不开发旧档迁移器。
- 马匹不增加力量、耐力、柔软性、瞬发力等独立能力数值。
- 表面适性只有草地、泥地，各自为A／B／C／G四档；不再有表面S档及各地区表面档位。
- 赛场类型适性只有瞬发、持久、消耗，各自为◎／○／△。
- 每个赛程只有一种主类型，强度只有Ⅰ／Ⅱ，与G1/G2等赛事格付分开。
- 赛程按“马场＋表面＋距离＋路线”识别，多个赛事共用赛程属性。
- 现实和虚构赛程共用结构与计算规则。
- 赛场类型适性只在赛前修正一次本场能力，不改变马匹永久基础能力，不在比赛各阶段重复加入。
- 保留地理信息用于赛历、骑手、资格与运输；删除的是地理信息对适性修正的决定作用。
- 真实适性与玩家认知分开，未知不是第四档真实适性。
- 为未来遗传保留字段与快照入口，不在此次实现复杂遗传算法。
- 实验版放在当前项目中，以可复用模块实现；存储与当前正式版隔离。

### 暂定数值，不视为最终定案

| 表面适性 | A | B | C | G |
| --- | ---: | ---: | ---: | ---: |
| 首发修正 | 0 | −5 | −10 | −20 |

第四阶段验收后，用户将G由−25调整为−20；其余草泥修正维持不变。

| 类型适性 | Ⅰ级 | Ⅱ级 |
| --- | ---: | ---: |
| ◎ | +2 | +4 |
| ○ | 0 | −1 |
| △ | −2 | −4 |

以上类型修正为用户初案。第四阶段可对照Ⅱ级+4／0／−4等简单候选，不在开发其他模块时随意改表。

组合参考：普通○○△、◎△△；稍优秀◎○△、○○○；更少见◎○○、◎◎△；极少数◎◎○；不希望大量◎◎◎。比例尚未确定，不把此清单解释为所有其他组合一律非法。

### 此次不做

高精度现实数据库、复杂自动分类、天气或配速动态改类型、额外核心类别、完整适性发现、复杂遗传、海外运输新适性以及少数赛道专属规则。既有天气／重地、疲劳和距离规则先保留，不新增相关机制，不因“消耗型”重复施加惩罚。

## 三、第一阶段：核心机制实验版（已完成，2026-09-22）

目标：不依赖全量比赛库或正式马匹生成，验证“马匹适性×赛程→一次性能力修正→现有比赛”。

### 工作内容

1. 新增独立纯规则模块，定义两个适性枚举、三类型、两强度和集中修正表。表面四档与类型三档不得混用枚举或查表。
2. 固定基础数据结构及解析接口。代码命名可按项目习惯调整，语义保持一致：

```js
horse.surfaceGrades = { grass: "A", dirt: "C" };
horse.trackAptitudes = { burst: "◎", sustained: "○", attrition: "△" };
// trackAptitudes直接使用◎/○/△，与surfaceGrades的A/B/C/G分开校验。

const courseProfile = {
  id: "course-demo-001",
  trackId: "track-demo",
  courseConfigId: "track-demo:outer",
  surface: "草地",
  distance: 2400,
  type: "burst",
  intensity: 2
};
race.courseProfileId = courseProfile.id;
```

3. 设置6～12条人工样例，覆盖六种类型强度组合；使用已确认的现实资料或明确标记为虚构的样例，未经核实的现实分类不得伪装为定案。
4. 建实验页面：手工设置能力、两项表面档位、三项类型档位，选择赛程，显示完整修正明细并试跑比赛。先不实现正式生成概率和大型管理界面。
5. 将新规则能力计算接到可复用接口，复用现有实体马比赛阶段，全部实验参赛马使用相同规则。测试初期固定成熟度、气性、重地等其他条件，再检查组合交互。
6. 比赛计算输出结构化摘要，至少包含表面档位与修正、courseProfileId、类型、强度、对应档位与修正、其他修正、rawAbility、最终ability及规则版本。后续评语读取摘要，不重复计算或掷骰。
7. 实验页显式显示“开发中，数值未定”；使用独立存储键／数据库命名，不读取或覆盖当前正式进度。只做最小保存重载，不扩建存档管理系统。

### 主要模块

- 新增建议：`js/rules/track-aptitude.js`、`js/data/course-profiles.js`，以及实验页和最小控制脚本；具体文件名在实现时记录。
- 接口位置：`js/rules/horse-generator.js`的calcRaceAbility及`js/rules/race-simulator.js`的实体马比赛入口。
- 新模块在实际使用的页面、后台模拟和测试加载器中正确加载，不为尚未启用的入口提前引入副作用。

### 完成标准

- 18个类型×强度×档位组合结果正确；表面四档及叠加结果正确。
- 其他修正为零时，80、草地A、瞬发◎、瞬发Ⅱ得到84；△得到76。
- 改变无关的两个类型档位不影响当场；预览、重复计算、连续比赛不累加到strength。
- 同条件下最终阶段总分的变化与能力修正一致，三个比赛阶段不重复加分。
- 实验记录可保存重开，正式存储未被改写。
- 实验赛程必须显式携带样例档案；正式比赛库无法确认实体赛场时，使用明确标记、可替换的低置信度Ⅰ级巡回模板，不把国家直接当作赛场类型。

此阶段不生成正式练马师评语，只显示中性的计算明细。评语第五阶段实现，避免此时引入旧地区判断。

### 实施记录

- 实验入口：[赛场适性系统实验版](../track-aptitude-lab.html)。可手工配置实验马与对照马的基础能力、草泥A/B/C/G和瞬发／持久／消耗◎/○/△，选择六条明确标为虚构的样例赛程，查看赛前计算明细并运行一场实验赛。
- 新增核心模块：`js/rules/track-aptitude.js`。它集中校验马匹与赛程、处理草泥／类型两张独立修正表；正式解析优先共享赛程档案，资料不足时由档案库返回明确标记的低置信度Ⅰ级模板。
- 新增样例资料：`js/data/course-profiles.js`。六条虚构赛程覆盖瞬发、持久、消耗的Ⅰ／Ⅱ级；尚未代表现实赛场分类结论。
- 实验页与独立存储：`track-aptitude-lab.html`、`js/track-aptitude-lab.js`、`css/track-aptitude-lab.css`。唯一存储键为`keiba-track-aptitude-lab-v1`，不会读取、写入或清除正式进度键。
- 复用入口：`HorseRules.calcRaceAbility`只在赛事显式携带`courseProfile`时调用实验规则；`RaceRules.simulateWorldRace`只在`includeAbilityCalculations`选项为真时回传本场摘要及阶段明细。现有正式赛事路径保持原有结果结构。
- 构建更新：`scripts/build-web.js`现在复制根目录全部HTML页面，生产构建会包含实验入口，而不只包含首页。
- 自动验证：新增`tests/track-aptitude.test.js`与`tests/track-aptitude-ui.test.js`，覆盖18种类型×强度×档位、草泥四档叠加、80→84／76、低置信度模板、现有比赛阶段复用、独立存储、页面赛程选择和试跑。
- 已运行：`node --test tests/track-aptitude.test.js tests/track-aptitude-ui.test.js tests/build-web.test.js tests/syntax.test.js`（10项通过）；`npm run test:quick`（227项通过）；`node scripts/build-web.js`（确认实验页与所需脚本、样式进入`dist`）。

## 四、第二阶段：遍历比赛库并更新赛程属性

目标：为当前可用比赛建立可追踪、可共用的赛程关系，消除地区适性的计算依赖。

### 工作内容

1. 自动清点当前赛事来源、生成型赛事及主席世界实际启用赛事。审阅时原始注册表为2170条；开发时重新统计，不能把这个数量当固定验收值。
2. 整理“赛事→实际马场→路线→表面→距离”的关系，再按唯一组合去重形成赛程。旧course字段在海外可能只是国家，不能直接当马场标识。
3. 复用`chairman-venues.js`和主席世界已有trackId、courseConfigId。补齐普通模式的关联，不建立两套不相通的马场身份。
4. 先选择一批代表性赛程校准分类口径，再分批遍历全库。批量更新的是共享赛程与引用，不给同一赛程下的每个赛事各自维护一份类型。
5. 分类依据用户的三种定义：前段压力、提速时点、高速输出持续时间和路线整体倾向。距离不是消耗类型的替代指标，表面不是类型的替代指标。
6. 难以明确但有依据的赛程选择最接近的一类并优先Ⅰ级；AI可输出较低置信度供复核。完全没有马场或路线资料的项目挂接名称明确、来源可追踪的低置信度Ⅰ级模板，后续再替换为实体赛场档案。
7. 现实资料查询时优先官方马场与赛事资料，记录来源及人工判断理由。置信度、来源是整理元数据，不参与比赛修正。
8. 处理轮换举办地、同场多路线、自动生成条件赛和自定义赛事。先解析本届实际举办场地，再匹配赛程；锁定或完成的届次保留当时快照。
9. 检查makeNamedRace等字段筛选构造器，确保新引用不会在载入时丢失。分享包如在本阶段开放，也要携带赛程及关联重映射。

### 交付物

- 共享赛程数据及赛事关联。
- 机器可读的覆盖报告，区分已确认、低置信度模板、重复／冲突和暂未启用；分类元数据明确哪些是人工游戏判断。
- 简短分类说明，记录判断口径及争议项，不在其中新增核心类别。

### 完成标准

- 已遍历全部当前比赛入口，没有静默遗漏的生成赛事或自定义入口。
- 新规则中启用的赛事全部有可解析赛程；尚未落实到实体赛场的项目必须有明确的低置信度模板与替换入口，不得以国家属性冒充赛场属性。
- 同赛程共用属性，不同距离／路线不错误合并；真实与虚构采用同一校验和计算。
- 分类更改只影响未来未冻结比赛。

主要模块：`js/data/races/core.js`、各地区赛事数据、`js/data/chairman-venues.js`、`js/rules/chairman-world.js`、赛程数据模块，以及自定义赛事和内容包相关入口。

### 实施记录（已完成，2026-09-22）

- 新增共享档案库：`js/data/race-course-profiles.js`。档案以马场稳定键、表面、距离和路线 ID 共同标识，并保存三类型、Ⅰ／Ⅱ、人工确认状态、置信度和规则来源。正式切换后的赛事仅保留 `courseProfileId`、`courseRouteId`、`courseRouteName` 引用，不复制类型或等级；本阶段通过解析器取得引用，不改写已命名原始比赛库。
- 首批数据：录入用户提供的 17 条日本赛程模板，关联 24 项日本中央 G1。已核实的中山、阪神和京都赛事保留内／外回；当前阶段对原始资料未写内／外回的赛事统一使用 `standard` 路线低置信度档案，避免路线细节阻塞接入。
- 官方路线校验与初判：新增 JRA 十场的官方平地距离／路线目录，作为条件赛生成器、档案库与审计的单一来源。为其中路线唯一的赛事建立低置信度Ⅰ级独立档案；其类型依据赛道结构按既定判定树初判，保留人工调整入口，且不覆盖用户确认的17条模板。另以 JRA 官方比赛页补齐13场命名赛事的内／外回。
- 中央条件赛重排：条件赛生成时保留原距离，优先原马场、同举办组和同档期地方场，再选择可承办的中央马场，并写入路线。原先543条不存在的“马场＋表面＋距离”组合已清零，不再把真实马场名作为无效的虚构赛程使用。
- 补充赛场与全库挂接：新增地方赛场、沙田、澳洲主要赛场、美丹、阿卜杜勒阿齐兹国王赛马场与圣伊西德罗的低置信度Ⅰ级赛程档案；具名赛事优先挂接实际赛场。仅写国家名的美国、欧洲生成条件赛则挂接到名称明确的巡回赛场模板，而非以国家代替赛场。全库审计当前为 2170 场全部已挂接、待补 0、引用冲突 0；身份中 1523 条路线明确或已合并内／外回、647 条为实际赛场或巡回模板，`ambiguous`、`invalid`、`unavailable` 均为 0。脚本为 `npm run audit:course-profiles`，可用 `-- --write` 写入 `artifacts/track-aptitude-course-coverage.json`。
- JBC 届次举办地组：新增可供所有模式调用的 `venueGroups.jbc` 与 `resolveVenueForRace`／`resolveForEdition`／`resolveEditionRace`。JBC 经典赛、短途赛和雌马经典赛同届共用实际举办地；2024 佐贺、2025 船桥、2026 金泽使用官方覆写，2027 起由可调整的模拟轮换表解析。2026 年另按官方条件覆写为金泽泥地2100／1400／1500米，避免只更换马场而仍沿用基准距离。将年份传给 `applyToRace` 后，可物化该届实际赛场和距离的档案引用；未给年份时仍保留“JBC地方交流轮换赛场”低置信度默认档案，兼容没有届次概念的既有调用。
- 主席模式 JBC 举办组：日本参考世界已纳入三场 JBC 泥地 G1 与大井、船桥、川崎、盛冈、名古屋、佐贺、金泽七座候选地方马场。其年度轮换、单年指定和冻结快照复用育马者杯的举办组机制；主席世界使用游戏年份的模拟轮换，普通赛事库的现实届次则仍由上述年度覆写解析。
- 赛事构造与入口：`makeNamedRace` 保留显式路线和档案字段；首页、主席后台与测试加载器均在比赛库加载后加载档案模块。共享解析器为当前比赛提供档案引用，但不在载入时写入原始比赛对象；主席世界在本届实际举办地仍匹配已确认路线时才携带引用，改址或轮换到其他路线会清除该引用。冻结届次快照也保留这些字段。
- 阶段边界：巡回赛场模板与未细分路线的 `standard` 档案均为低置信度Ⅰ级，只用于完成统一赛程接入，不能视为现实赛道的最终分类。第三阶段已将共享解析接入正式赛前能力计算。
- 验证记录：赛程档案与主席世界的针对性测试覆盖共享解析、显式物化与改址清除；新规则下的确定性模拟摘要已更新并受测试保护。`npm run audit:course-profiles` 审计为2170场全部已配置、0待处理、0无效；`npm run test:quick`（242项）和`npm run build:web`均已通过。
- 判定细则和日本基线见《[赛场适性判定与日本赛程基线](赛场适性判定与日本赛程基线.md)》。

第二阶段的数据覆盖已完成。下一批工作是：以赛事主办方资料复核低置信度实体赛场档案；按需要将 `standard` 路线拆回内／外回；在主办方公布未来 JBC 条件后补充其年度举办地和距离覆写。第三阶段开始前，巡回模板与实体赛场档案均应保留人工修订入口。

## 五、第三阶段：赛马属性与正式入口接入（已完成，2026-09-22）

目标：所有保留开放的实体马来源均使用两项表面四档和三项类型适性，接入现有比赛流程。

### 工作内容

- 替换grass/dirt地区映射及courseGrades的生成和读取；新计算不再叠加旧地区、日本马场修正。
- 用组合模板及其排列生成三项类型适性，集中设置试验权重；不独立抽三项，也不把高基础能力强制绑定到高适性质量。
- 草泥生成与类型适性独立。可先采用“普通马至少一个表面A”的生成建议，但记录为可调策略，不限制手工特殊个体。
- surfacePref如保留，只作为生成模板或从最终档位派生的描述，不与surfaceGrades形成矛盾的两份真值。
- 接入普通建马、肉鸽候选、剧情模板、主席补充马群、手工马、育种子代和父母快照。此阶段只保证育种能携带新字段；新适性可先使用普通生成器，不要求完成遗传算法。
- 更新编辑器、马匹展示、CSV／JSON、存储、页面及后台模拟入口；取消旧格式兼容回退。旧存档不自动当作新存档读取，不主动清除用户文件或浏览器数据。
- 区分完整实体马与历史单场ability／historicalScore。审计所有对手入口，逐项记录“重新构造基础能力后加适性”或“明确视为已含条件的结果，不重复修正”的处理。不能对已有历史表现直接叠加一次适性，也不能遗忘对手语义。
- 检查肉鸽可行路线筛选和主席自动选赛。先保证不再访问已删除字段；若自动择赛尚未识别类型，在第四阶段报告中明确，不把其结果当作专精型的最终平衡结论。
- 正式评语第五阶段才完成，中间版本不调用会读取旧字段的适性评语；相关实验显示使用中性明细或明确的“评语待适配”，不输出误导判断。

### 完成标准

- 所有开放马匹来源生成合法且完整的新字段；出生／创建后刷新不重抽。
- 草泥和类型真值可独立编辑、计算、保存、重载。
- 新比赛只走新适性公式；距离、重地、成熟、气性、疲劳等既有修正没有重复或丢失。
- 对手能力语义有明确处理，玩家与其他实体马遵守相同规则。
- 已删除字段的运行时读取已清理；所有未适配入口显式列为未完成，不靠假旧字段维持运行。

主要模块：`horse-generator.js`、`era.js`、`roguelike.js`、`chairman.js`、`chairman-breeding.js`、`chairman-world.js`、`bloodlines.js`、历史对手相关规则，以及应用、编辑、导入导出和存储入口。

### 实施记录

- 正式赛马数据固定为 `surfaceGrades: { grass, dirt }` 与 `trackAptitudes: { burst, sustained, attrition }`。草泥仅允许 A／B／C／G，类型仅允许 ◎／○／△；旧地区草泥和日本马场字段不再生成、读取或参与计算。
- 正式比赛在赛前统一解析共享赛程档案并一次性应用草泥和赛场类型修正。能力摘要记录实际档案、表面修正与类型修正；距离、重地、成熟、气性和疲劳仍沿用原有链路。历史单场分数继续视为已计算结果，不重复叠加适性。
- 生成器使用可调的组合权重生成类型适性：○○△、◎△△为主，◎◎○极少，排除◎◎◎；组合会随机排列到三种类型，且不依赖基础能力。草泥与类型独立生成，`surfacePref`仅从草泥真值派生为展示描述。
- 普通建马、调试面板、肉鸽候选与草泥调教、剧情马、主席马群、手工马、CSV、编辑器、繁殖子代和受胎快照均已接入新字段。主席模式轮换赛事按本届实际赛场解析档案；虚构／自定义赛场和资料未落实到实体马场的既有赛事使用明确标记的低置信度Ⅰ级巡回模板，后续可直接替换为实体赛场档案。
- 比赛库审计为 **2170 场已配置、0 待处理、0 无效**。正式赛前计算遍历同一2170场比赛时无缺档。
- 普通、肉鸽、剧情存档版本已提升并拒绝旧规则数据，避免旧字段被误读。主席模式的正式旧档清理与部署页面提示在第六阶段统一处理。
- 练马师场地评语暂显示中性过渡提示；赛后地域认知不会再根据新比赛结果写入旧地区适性。第五阶段再以草泥和三种类型重建评语、认知和赛后归因。
- 验证：赛程档案、类型修正、肉鸽、剧情、主席繁殖／轮换／编辑与全库遍历均通过定向测试；完整快速回归在本阶段收尾时重新执行。

## 六、第四阶段：规则数值平衡研究

目标：用实际赛程覆盖和新马匹生成验证专精／泛用价值，确定首发数值。

### 工作内容

1. 固定随机种子与其余条件做成对对照，再使用多个种子检查稳定性。对照方案尽量共用随机条件，避免新增抽样步骤把随机差异误当规则收益。
2. 比较所有主要组合及其排列，覆盖表面A/B/C/G、Ⅰ/Ⅱ、同能力与不同能力的马。
3. 同时观察均匀赛历、实际赛历、偏科赛历和主动择赛。按表面、距离、年龄、资格、地区可达性统计机会，不只看全库三类型总数。
4. 指标至少包括胜率、平均名次、有效参赛机会和能力修正分布。记录样本量、随机种子、配置与不确定性，不以单次幸运赛果定案。
5. 对比原始Ⅱ级+4/−1/−4与简单对照+4/0/−4；检查草泥G的惩罚是否过重。先调集中表和生成权重，避免用特殊赛道规则修补。
6. 检查普通模式60能力下限、主席无该下限、旧表面S加成取消、距离惩罚及历史对手标尺的交互。如果拟改其他规则，明确列出变化及理由，不暗中扩大改动。
7. 如需验证自动赛季，先让选赛逻辑具备最低限度的类型辨识或明确限定为手动择赛实验。未来隐藏适性环境下使用公开表现／已知信息；直接读取真值的理想择赛只能作为标明的对照组。

### 完成标准

- 提交可复现的对照报告，明确○○○和◎△△各自适用场景与限制。
- 不要求所有不同稀有度组合等强，也不以“三类型全球数量相等”代替可玩性。
- 给出首发修正表、生成权重和仍有不确定性的项目。
- 规则表变更后重新运行相关计算与保存验证；实测发现问题可返回第二／第三阶段修正，并更新状态，不把阶段顺序当作不能回退的瀑布流程。

### 实施记录（已完成，2026-09-22）

- 新增只读分析脚本 `scripts/analyze-track-aptitude-balance.js` 与命令 `npm run analyze:track-aptitude`。它使用固定种子、22种现有组合排列、六种类型强度与每格600次双马模拟，不改写规则、比赛库或玩家存档。
- 分别按均衡赛历、2170场全库赛历与353场已确认赛程汇总结果，并单独检查草泥A/B/C/G和普通模式60能力下限。
- 结论：验收后将草泥G由−25调整为−20，其余草泥修正、类型修正和生成权重维持不变。○○○没有在随机参赛中明显压制◎○△；◎△△在匹配自身◎的赛程中有明确收益；G仍为后续实战观察项。详细依据见《[赛场适性系统第四阶段平衡分析报告](赛场适性系统第四阶段平衡分析报告.md)》。

## 七、第五阶段：练马师评语更新

目标：使用新维度准确解释马匹特点与比赛表现，保留既有观察不确定性。

### 工作内容

- 赛前分开生成“草地／泥地适性”与“瞬发／持久／消耗适性”评语；删除日本场、欧洲场等旧适性目标。
- 保留现有准确、模糊、未知、误判机制和结构化claim；练马师的身份地区继续保留，专业判断目标重新适配，具体人物专长另行记录。
- 赛后读取第一阶段确定的能力摘要，分别判断表面不合、类型不合、距离等问题；不重掷气性，不根据名次反推真实档位。
- 当前规则若仍保留○Ⅱ为−1，不将所有负修正都诊断为明显不适应。△是类型短板候选，◎也可能因其他原因落败。
- 多因素并存时允许措辞保留余地，不把其中一项认定为唯一败因。
- 更新adaptation-hints的目标为表面和类型键，保留真实值与认知分离，不通过中文地区标签推断目标。
- 一次观察只更新相关维度；不将“赢了”或“适性没问题”直接变成全部档位确认。内部知道是否误判，不代表玩家应看到真假标签。
- 基础认知字段与现有评语写入路径接通即可，多场发现阈值、完整证据模型和血统推断仍不做。

### 完成标准

- 评语及认知不再读取已删除地区适性字段。
- 草泥与赛场类型原因不混淆，文本不暗示新增独立耐力或爆发力数值。
- 赛后评语、计算明细与认知记录目标一致；误判只影响认知，不修改真实适性。
- 覆盖○Ⅱ负值、◎落败、△获胜、多因素不利和无足够证据等代表案例。

主要模块：`js/rules/comments.js`、`post-race-comments.js`、`adaptation-hints.js`、相关UI和帮助说明。

第五阶段已完成（2026-09-22）。准确判断内部保留原来的非常准确／基本准确；自然语言优化后，类型按三／二／一项控制信息量，草泥按两／一／一项控制信息量，误判只说一个错误目标且与模糊语气相同。原胜退简评与实力、发挥分析保留。实现细节、实际文件、测试与浏览器证据见[第五阶段评语验收](赛场适性系统第五阶段评语验收.md)。

## 八、第六阶段：整体验证与发布准备

目标：确认从新开档到比赛、评语、保存和后代生成的整体链路可用，再准备正式切换。

### 验证范围

- 普通、传奇、肉鸽、剧情、主席等仍开放模式的新建、选择比赛、报名、运行、结算和保存重载。
- 页面与后台模拟使用同一规则及赛程数据，无脚本加载缺失。
- 现实／虚构、自定义、共享赛程、轮换举办地、年度冻结和历史记录。
- 马匹与赛程编辑、复制、CSV／JSON导入导出、内容分享中的引用完整性。
- 配种中的父母快照、已冻结后代及后续出生新字段完整性；不把这项验证扩大为新遗传算法研究。
- 评语、玩家认知、公开显示与调试真值的边界。
- 新存档正常读写，旧档被清楚识别为不支持，实验数据不会误入正式存储。
- 常规测试、数据完整性检查、生产构建与关键桌面／手机交互。长期模拟规模依据已发现风险决定，不机械增加无关检查。

### 部署页面提示

开发期提示“新规则正式上线后不兼容旧存档，需要重新开始”，不要声称正在开发就会删除现有进度。只有在实验存储隔离验证通过后，才能承诺“实验版不影响正式版存档”。

警告文案与上线动作属于本阶段的发布准备，本次文档工作没有实际添加页面警告，也没有部署。是否执行部署遵循届时用户授权，不以本文代替部署指令。

### 完成标准

- 保留开放的模式与入口全部通过验证，没有旧公式暗中参与新比赛。
- 已启用赛事和实体马数据覆盖完整；未启用内容有明确说明，不用默认值伪装已配置。
- 提交验收记录、已知限制及规则变化说明。
- 只有整体验证通过后，才把实验入口的模块切换为正式入口使用；实验页面可继续作为开发调试工具。
