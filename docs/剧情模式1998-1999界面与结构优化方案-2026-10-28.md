# 剧情模式1998—1999界面与结构优化方案

日期：2026-10-28。工作区：`.claude/worktrees/story-mode`；分支：`feat/story-mode`。

## 1. 本轮结论与边界

**先整理玩家的信息与操作路径，再随职责整理代码；不先大搬年度数据，也不扩展2000年。** 当前两季内容已有足够体量，主要问题是“正在经历的剧情”和“可供查阅的资料”混排，而非缺少更多年份。

本文是现状梳理和分批建议，尚未实施UI、目录或玩法修改，不构成用户对全部批次的实施授权。

- 保留报刊式排版、纸色正文、暗绿与暖金气质；不换框架、模块系统或整站主题。
- 不重写1999定稿正文，不借优化重新润色全部1998正文。1998仍为draft，不等于此前未做事实与文风工作。
- 不改资格、模拟强度、史实赛果、稳定ID、随机数消费、事件顺序及既有新闻/剧情快照。
- 不提交、不推送、不切分支、不stash；不改changelog、首页状态、版本号；不手改dist，不清理已有未跟踪资料。
- 用户已结束此前验收，本轮没有重开宽屏或全季验收。后续若实施UI，只检查该批变化本身，不借此续做旧验收清单。

## 2. 当前玩家路径与代码证据

```text
首页 → 剧本菜单 → 生成候选 → 马房相遇/命名 → 当前剧情
                    ↑ 有存档时继续                 ↓
                  重开路线               选项/赛程报名/推进
                                                   ↓
                                          比赛与赛后 → 跨年 → 生涯结束
```

局内目前并行放置：

- 顶栏：赛程手册、报纸箱、剧本菜单、返回主页。
- 主列：当前场景 → 结束总结 → 全部生涯纪事 → 已发生年鉴 → 两季百科。
- 侧栏：战绩、主战骑手、适距、出道前评估、标签、提前退役。
- 两个抽屉：全赛程、全部新闻。

主要依据：[era-render.js](../js/ui/era-render.js)第12—53行；[app.js](../js/app.js)剧情状态、存取和事件分发；[era.css](../css/era.css)。当前render文件只有55行，但核心是超长模板，不能用行数判断复杂度。

|现状|实际影响|处理优先级|
|---|---|---|
|当前剧情、历史纪事、年鉴、百科全部在一条长主列|本轮行动与资料查阅缺少清晰层级，资料随进度增长|最高|
|赛程一次列出返回的全部项目，包含不可报名项|玩家需要在条件和原因中自行寻找下一场；不应靠删掉不可报赛事解决|高|
|报纸箱全部列出，已有read字段但没有筛选组织|“刚发生什么”不够突出，已读操作可能带来全页重绘|中高|
|百科已有年份、类别和稳定ID，但界面全部details展开入口混排|资料齐全却缺少目录，跨年和类别查找成本高|高|
|出道前评估常驻，prototypeNotice在局内重复整段显示|背景说明与当前剧情、下一步操作争夺空间|中|
|render整体替换container.innerHTML|浏览态可能丢失；需在实施时定向检查焦点、滚动和details展开，不能仅据静态代码宣布已证实全部缺陷|高|
|“确认名字，进入${label}赛季”使用普通引号|源码确定不会插值，命名按钮可能显示字面占位串|首批小修|
|两季结束标题叫“年度总结”，指标取run.summary整局累计|容易把1998—1999累计误解为单年统计|首批小修|

另有应用层调用`previewSceneChoice`、`completeTransientScene`，而当前EraRules导出表未见对应接口。这是**已复核的静态接口不一致**，尚未确认现有UI是否能触发，不能称已发生运行故障；控制器迁移前需核对入口可达性，不擅自删代码或补造规则。

## 3. 建议的信息架构

### 3.1 局内默认页：赛季现场

```text
日期 / 马名 / 当前年份          赛程  报纸（未读数）  更多
─────────────────────────────────────────────────
当前剧情：标题、正文、原有选项       马房摘要
                                   战绩 / 适距
当前报名：比赛、日期、条件           完整档案入口
─────────────────────────────────────────────────
赛季现场 | 生涯纪事 | 赛事年鉴 | 名马与名场面
```

这是结构示意，不是已确定的视觉稿。窄屏不强制挤成四列，导航可换行或使用紧凑选择器；不新增悬浮层遮挡剧情选项。

- 默认保留当前剧情、选项和已报名赛事摘要；选项内容及原有推进规则不变。
- 不另造一个绕过剧情选项的“继续”快捷按钮，不让导航动作推进日期。
- “更多”承接剧本菜单、返回主页、玩法与口径说明；提前退役放在完整档案的独立区域，保留确认，不能与普通导航紧邻误触。
- 审核状态仍逐项显示；可弱化视觉权重，但不隐藏1998草稿，不把新闻快照追认为final。
- 无当前场景、命名前、已有报名、待播年终、已结束等状态分别有清晰空态，不用新增规则补空态。

### 3.2 赛程：先找得到，再看得全

- 默认“后续赛程”，显示已报名置顶以及未来项目；“可报名”作为可切换筛选，不让默认列表因暂时无资格而完全空白。
- 保留“全部”入口，提供年份/月度分组；既有enabled/status/reason是唯一资格依据，UI不重新计算。
- 不可报名原因贴近赛事，已结算/未标定与资格不符分开标识。
- 报名/取消后回到可辨认的位置并显示结果；不改原自动保存时点。

### 3.3 报纸、纪事、年鉴、百科各归其位

|区域|默认组织|保留的口径|
|---|---|---|
|报纸箱|最新在前；全部/未读、年份筛选；显示未读数|读取已有快照；不重算正文或批量追认状态；查看列表本身不自动标已读|
|生涯纪事|年份/月度分组，最新在前，可回看|使用已存content与日期，不用当前源文覆盖历史|
|赛事年鉴|年份/月度目录；已发生列表，可筛“本局参赛”|史实与本局结果并列；未来赛事不泄露本局结果|
|名马与名场面|年份＋名马/名场面/年度类别；标题检索，保留全部入口|继续允许查阅全年史实回顾；明确这是史实资料，非本局预言|

年鉴与百科互相关联优先复用raceId/horseId；无明确关联不模糊猜配。第一阶段不做全文搜索、复杂分页或新数据索引，先让现有字段真正成为目录。

## 4. 代码与目录职责

### 4.1 不需要推倒的部分

现有`js/data/era/`已按年鉴、赛历、表现标定、片段、简讯、正文和年份分组；两季属于同一scenario，不应改成两套年度引擎。world、conditions、storylets、news、narrative、save已有职责边界，当前不为目录整齐再次拆散。

保留年度文件及注册顺序。`almanac/registry.js`跨年同马只补空字段，迁移顺序也可能改变结果，不能随意排序。

### 4.2 目标职责（建议路径，实施前定名）

|位置|应负责|不应负责|
|---|---|---|
|`js/app.js`|全应用装配、跨模式导航|剧情专属按钮分发、全部视图状态与存取细节|
|新增`js/era-app.js`|剧情控制器：动作分发、临时视图、存取编排、调用刷新|赛事计算、剧情条件、正文生成|
|`js/ui/era-render.js`|保留EraUI公开入口与整体布局|一条超长模板包办全部资料区|
|视实际体量新增`js/ui/era-records-render.js`|纪事、年鉴、百科等只读资料渲染|写run、推进时间、判断报名资格|
|`css/era.css`|剧情主题、布局、组件、响应式，按区域整理|顺手改全站theme或未经引用核对删除旧选择器|
|`js/rules/era*.js`|保留当前规则职责与对外接口|承载标签选中态、抽屉焦点等界面状态|

先抽具名渲染函数，使模板可读；体量证明有必要后再拆物理文件，不为凑目录创建大量小文件。新增脚本同步`index.html`与`tests/helpers/project-loader.js`手工加载清单，继续IIFE和window.Keiba。控制器和渲染都不得消费随机数。

临时视图状态如activePanel、筛选、展开条目、抽屉来源焦点不进入run或存档。存档key、版本、损坏档保护、阻止覆盖机制、自动保存时点均保持原样。页面跳转或新局要重置临时状态，不能串局。

暂不拆`era.js`赛事结算。那是有随机/事件时序风险的规则重构，不是当前UI产品化所必需；只有后续出现具体维护瓶颈才另列范围。

## 5. 分批顺序与交付标准

各批按顺序落地，不并行写同一组app/render/CSS；每批结束可单独审阅，不要求一次批准全部。

### 第一批：主界面层级与局内导航（推荐下一步）

- 把当前剧情设为默认主区，将纪事、年鉴、百科切换为按需显示；先不做搜索和复杂筛选。
- 马房保留短摘要，完整评估按需展开；局内说明归入说明入口，不改scenario里的原文。
- 修命名按钮插值；结束页明确“两季生涯总结/累计”，不改场景正文。
- 先在现有render里拆具名函数；视图状态通过options传入，由app管理，不写run。
- 核对静态接口疑点的可达性；如需改规则，不夹带实施，先单列结论。
- 最小验证：各面板可往返、选择仍走原事件、1998/1999审核状态不变；render前后run不变；切面板不写档、不推进；结束累计口径与命名按钮正确。

### 第二批：赛程、报纸与资料目录

- 增加第3节的年份/月度、可报名/全部、未读及百科类别/标题检索。
- 筛选只改变显示，不改变底层数组、资格和事件。
- 确保空筛选有提示和清除入口；结果计数跟随筛选，全年总数另列。
- 最小验证：跨年、空列表、取消筛选、报名/取消、标已读、史实与本局人数及未发生资料边界；操作后焦点/滚动/展开状态有明确结果。

### 第三批：控制器与样式收拢

- 从app抽剧情专属编排，显式注入storage、refresh、跨模式导航、confirm/alert；不同时重构结算。
- 视体量拆资料渲染；CSS按主题/布局/组件/响应式整理，核对动态类及主题覆盖后才删除确属无引用内容。
- 同步加载清单和测试入口；不移动年度数据，不重命名稳定ID。
- 最小验证：固定种子相同动作的run/rngState/事件顺序一致；候选、命名、跨年、恢复、异常存储保护不变；其他模式入口无回归。

### 第四批：两季体验细节收尾

在前三批稳定后，只整理当前年份提示、跨年纪事定位、资料互链、结束后回看路径和空态。先列出具体差异，再逐项决定是否改动；不自动扩展成正文改写、1998定稿或2000开发。

所有实际UI批次都需用隔离存储运行真实应用，检查新增交互、适用的桌面/手机布局及控制台；运行对应UI专项，收尾按项目约定执行`npm test`、`npm run build:web`。这是未来改动验证要求，不是本轮已执行的结果，也不是恢复此前终止的全量验收。

## 6. 本轮实际产出与未做项

本轮只读核对源码、最新移交说明、状态与既有验收边界，并编写本文。架构代理结果已对关键app存取、EraRules导出、UI模板进行交叉核对；静态疑点不代替运行结论。

未修改游戏源码或已有交接记录，未启动浏览器、测试、构建或长期模拟；未提交、推送、切分支、stash或部署。既有448项测试等结果仅属此前记录，不能作为本方案已经实现的证明。
