# 赛场适性系统：审阅与第一阶段计划

> 后续开发以[《赛场适性系统分阶段开发方案》](赛场适性系统分阶段开发方案.md)为准。最新顺序为：核心实验版→比赛库更新→赛马属性接入→数值平衡→练马师评语→整体验证。本文件保留初步审阅记录，其中第一阶段同步开发评语的早期建议已被新顺序替代；核心阶段只需预留评语所需的计算摘要。

审阅日期：2026-09-21。基于当前工作区，包含尚未提交的项目修改。本轮只编写和更新本文档，没有修改玩法代码。

已确认的开发前提：本次为规则基础重置，放弃旧存档兼容，不保留双轨计算或开发旧档迁移；草地、泥地各自采用A／B／C／G四档。练马师评语的基础适配纳入第一阶段建议范围，完整适性发现和遗传仍以后开发。

## 结论

方案整体可行。三种类型、两级强度、三档马匹适性足够完成目标；现有赛前能力计算有明确接入点，无须改写比赛阶段。

推荐先在开发版本的主席试验世界中，用少量赛程和手动参赛马跑通唯一的新规则。第一阶段不批量重建全部现实赛事和历史名马，不开发旧档迁移，也不重做自动选赛、遗传和完整适性发现。正式发布前，所有保留开放的模式都必须适配新结构；开发中的小范围验证不代表长期维持两套规则。

核心计算容易，完整替换的工作量主要来自旧地区适性承担了表面差异，以及不同模式的数据入口并不完全统一。不能把新增三个字段误当成全项目迁移已经完成。

原有能力公式为：

```text
成熟度调整后的能力
+ 地区／表面修正 surfaceMod
+ 日本马场修正 courseMod
+ 重地修正 heavyMod
+ 气性修正
- 距离惩罚
+ 赛前状态修正
→ 最后按模式处理能力下限
```

新规则应在相同位置形成：

```text
成熟度调整后的能力
+ 通用草地／泥地修正
+ 赛场类型修正（只取本赛程的一项）
+ 现有其他修正
→ 沿用该模式的能力下限
```

不改写 horse.strength，不在起跑、中盘、末盘再次加入适性。普通模式目前存在60点能力下限，主席实体马比赛显式关闭该下限；第一阶段保留这一既有差异，并测试修正在下限附近被截断的情况。

实测原始赛事注册表共2170条，均没有 trackId 或 courseConfigId。旧“地区＋course＋表面＋距离”有325种组合，但海外 course 可能只是国家，不能将325视为真实赛程数量。主席世界另行补充马场资料，因此适合先做试验入口。

## 二、规则判断

### 三种类型足够，但要统一定义

将其理解为赛程通常偏向的比赛形态，而非每次比赛必然发生的配速。瞬发偏晚段短时间兑现；持久偏较长时间高速输出；消耗偏前段压力、较少缓冲。允许现实上有重叠，人工取最接近者；难判优先Ⅰ级。

400～600米、700～1200米适合作为描述参考，不应编码成分类阈值。消耗不与距离、泥地或重地画等号，不依类型改变距离惩罚、疲劳或伤病，否则会产生额外重复计算。本轮未核实具体现实路线分类，也不把东京草2400等示例当作已确认分类。

### Ⅰ／Ⅱ值得保留

它只增加一个强度字段和一张查表，却能容纳“不明显”和“明显”的差别，也为难分类路线提供温和选项。不要与GⅠ／GⅡ赛事格付混淆：内部名用 intensity，与 raceClass、grade 分开。

### ◎／○／△足够

无需内部再增加隐藏连续能力。真实值只有三档，玩家认知可以另存未知／猜测／确认。第一阶段调试界面可全部显示；玩家评语及认知显示同步改用新字段，不要求同时完成多场发现流程。

### 原始数值可作为测试版本，不宜立刻定案

用户初案：Ⅰ级为+2／0／−2；Ⅱ级为+4／−1／−4。

在三类出赛机会各占三分之一、基础能力相同、没有择赛的假设下：

| 组合 | Ⅰ级平均修正 | Ⅱ级平均修正 |
| --- | ---: | ---: |
| ○○△ | −0.67 | −2.00 |
| ◎△△ | −0.67 | −1.33 |
| ◎○△ | 0.00 | −0.33 |
| ○○○ | 0.00 | −1.00 |
| ◎○○ | +0.67 | +0.67 |
| ◎◎△ | +0.67 | +1.33 |
| ◎◎○ | +1.33 | +2.33 |

因此：

- ○○○是无明显短板型，并不是每种赛程都最强。它逐项不弱于○○△，符合较高稀有度定位，不应要求两个不同质量档完全等价。
- ◎△△并不天然过弱：Ⅰ级平均与○○△相同，Ⅱ级平均反而更高。它能否有价值主要取决于优势类型是否有足够可达赛事。
- 与○○○相比，若优势类型出赛比例为p，则专精型在全Ⅰ级环境下平均修正为4p−2，在全Ⅱ级环境下为8p−4；超过泛用型分别需要p>50%和p>37.5%。这是能力修正的均值比较，不是赛季胜率保证。
- Ⅱ级并非Ⅰ级简单翻倍：◎比○高5点，○比△只高3点，额外偏向◎。如果希望Ⅱ级只放大原有差异，可以另测+4／0／−4，先不要自行替换初案。
- 同一组合的不同排列也需要分布，否则所有专精型都擅长同一类型。

按现有起跑、取位、末盘判定做离散概率枚举：两匹同基础能力、70能力骑手、无特殊末盘，排除其他条件差异，并以双方完赛为条件，平局各计一半时，净能力优势2／4／5／8点对应约63.1%／74.8%／79.8%／90.9%的对照胜率。该核算不是完整赛季模拟，也不含G1额外压力、不同气性和历史固定分。

这说明Ⅱ级◎与△的8点差距已经较强。应观察玩家是否愿意跨类型挑战，而非仅看“80变84似乎不多”。各类型在相关表面、距离、年龄、资格和赛期中的可达性，比全球简单数量均等更有意义。

## 三、推荐数据结构

推荐保留现有 JavaScript 对象风格，增加一个纯规则模块和一个赛程资料集合，不引入新的框架。

```js
// 马匹：三个定性适性。S/A/B只在此处映射◎/○/△。
horse.trackAptitudes = {
  burst: "S",       // 瞬发◎
  sustained: "A",   // 持久○
  attrition: "B"    // 消耗△
};

// 草地／泥地独立采用A/B/C/G四档，不再有地区键或S档。
// 第一阶段试验马可手工指定；不开发旧档转换。
horse.surfaceGrades = { grass: "A", dirt: "C" };

// 通用赛程记录：示意为虚构路线，分类不声称现实准确。
const courseProfile = {
  id: "course-demo-001",
  trackId: "track-demo",
  courseConfigId: "track-demo:outer",
  surface: "草地",
  distance: 2400,
  type: "burst",
  intensity: 2
};

// 同路线的不同赛事共享该引用；赛事名、格付、日期仍属于赛事。
race.courseProfileId = "course-demo-001";

// 未来可选：放入现有认知容器，不属于真实适性。
// knowledge.trackAptitudes.burst = { status: "unknown" };
```

赛程以“trackId＋表面＋距离＋courseConfigId”检查唯一性，id保持稳定；不要用会改名的显示名称作为关联键。路线没有细分时给出明确的普通路线标识，不需要建立更细的核心机制。

现实和虚构赛程使用完全相同结构。来源说明、置信度以后可作为可选元数据，与能力修正无关；低置信度不等于未知马匹适性，也不引入第三种强度。

主席世界可保存 `courseProfiles` 集合，先按现有世界元数据保存方式存储小集合，无须为试验另开数据库对象表；赛事包导入导出需显式携带并重映射引用。静态预设可放入 `js/data/course-profiles.js`，载入世界后由世界自己的资料作为计算来源。

轮换举办地的赛事不能永久绑定最初马场的赛程。必须先确定本届马场与路线，再取得对应距离赛程，并在现有届次快照中保存解析结果。第一阶段先限制试验赛事为固定举办地；启用轮换前补上这一分支与测试。

计算模块建议只公开：

```text
resolveCourseProfile(已解析举办地的赛事, 赛程集合)
calculateModifier(马匹适性, 赛程) → 类型、强度、档位、修正值
generateAptitudes(随机源, 组合权重) → 三项真实适性
```

修正表集中管理；计算时不掷骰，出生或创建时才抽取适性并保存。生成使用组合模板及其排列，不独立抽三项，以便直接控制◎◎◎的出现率。总质量可以从组合派生，第一阶段不另存“适性总分”，也不绑定基础能力高低。

## 四、必须先处理的边界，避免返工

1. **地区不能整体删除。** surfaceRegion、regionId等还服务于赛历筛选、骑手池、资格和运输。只解除它们与适性修正的绑定。
2. **保留草地／泥地差别。** 新surfaceGrades使用A/B/C/G四档，取消表面S档；赛场类型另用◎○△。新公式去掉旧地区及日本马场修正。四档的试验数值建议为0/−5/−10/−25，尚待确认与实测。
3. **不开发旧值映射。** “东京S”不能自动等于“瞬发◎”，“欧洲S”不能等于“持久◎”。基础重置后只维护一套新公式，删除旧字段读取、默认回退与对应生成逻辑。不把缺字段默认成稀有的○○○。旧存档入口只需提示规则不匹配、需要新开档，不自动读取为新档；本次文档修改不会删除用户现有存档。
4. **缺失与难分类分开。** 难分类且有人判断的赛程可定为最接近类型Ⅰ级；尚无数据的路线保持待配置。新规则试验开赛前要求完整配置，无须随机猜测或新增“中性”核心类型。
5. **别覆盖历史表现。** 正式记录保留本届赛程、使用的规则版本及实际修正。将来修改分类或马匹资料不能重算过去；不要求第一阶段提供完整重放系统。
6. **对手能力语义不能混淆。** 历史条目已有每场ability，部分模式又用固定historicalScore；本轮不要给这些预计算结果再次加适性。先用全部为实体马的主席比赛验证公平性。
7. **当前AI不会自动理解三种类型。** 现有选赛依据主要是公开赛绩、表面／距离等。第一阶段手动选赛；自动选赛随后至少纳入类型信息。未来未知适性下应使用已知信息或公开表现，避免直接读取隐藏真实值。两套主席选赛入口都要留意：chairman-scheduling.js与chairman-world.js。
8. **复用现有快照和显式字段入口。** 编辑器、CSV、父母快照、分享包、赛事构造器可能筛掉未声明字段。需要逐项接通，而非只改计算式。

## 五、未知适性和遗传

没有明显结构性障碍。真实值保持三项完整档位，认知另外存；竞赛计算只使用真实值。第一阶段不实现发现流程，但不把“？”写进真实值。

项目已经存在配种，不是从零开始：`inherited`会对属性组以约30%取父、30%取母、40%保留新生成结果；`geneticSnapshot`明确列出保存字段；offspring在受胎时生成并冻结。因此添加真实适性到快照和后代生成对象即可预留接口，第一阶段子代仍可使用普通组合生成器。

未来遗传可先决定组合质量，再决定三种类型的排列倾向，保留随机变异。不要现在定义显隐性、多基因或连续遗传数值；也不要让每项独立择优继承，导致几代后◎◎◎泛滥。父母认知、单场修正和成绩不应当作真实适性直接复制给子代。遗传算法更新不重抽已冻结offspring。

## 六、推荐最小范围及文件清单

- 六种类型强度组合都有样例，合计6～12条路线；真实路线使用已经人工确认的资料，虚构路线手工定义。
- 同一路线挂两个赛事，验证共用资料。
- 手工配置试验马及常见组合，随后接组合模板生成；先不确定正式概率。

## 七、实现顺序与测试

1. 固定新字段语义、规则版本和A/B/C/G表面处理，创建纯规则模块；不实现旧规则兼容分支。
2. 建少量赛程和手工马匹，验证18个“3类型×2强度×3档位”基本组合；改变未使用的两项适性不得影响当场修正。
3. 接calcRaceAbility。固定随机输入比较前后，验证80配◎Ⅱ变84、△Ⅱ变76，原strength不变，预览／重算不累计，原有三阶段没有重复加分。
4. 接主席新试验世界和最小编辑展示，同时适配基础评语与认知字段。让同赛程两个赛事取得一致分类，让现实／虚构对象同样通过解析与校验。
5. 记录摘要，测试新档保存重载、刷新不重抽、已完赛记录不随配置编辑改变、旧档不会误加载为新档；检查后台与页面结果一致。
6. 用固定随机种子比较组合，在均匀赛历、偏科赛历和主动择赛三种场景观察差距；随后决定是否需要调整Ⅱ级○值或整体幅度。

优先测试还包括：草地／泥地独立性、同马场不同距离／路线不误合并、缺少资料不静默映射地区、普通模式60下限与主席无下限的既有行为。后续启用轮换时测试实际举办地选择、冻结届次和包导入标识重映射；启用育种时测试父母和后代快照保留字段，不要求现在实现遗传平衡。

本轮已经执行的现有基线：`core-rules.test.js`、`chairman.test.js`、`chairman-regions.test.js`、`chairman-breeding.test.js`、`chairman-world.test.js`，合计67项全部通过。另做了上文平均修正和现有阶段概率枚举。没有实现新系统，因此这不是新功能验收，也未进行真实路线分类验证或全赛季平衡测试。

## 八、可以定案与需要等待实测的内容

**可以定案：** 三种类型；Ⅰ／Ⅱ；三档适性；单赛程一种主类型；地区与适性解耦；以马场、表面、距离、路线识别共享赛程；赛前只修正一次；真实值与认知分开；距离、疲劳和重地不由类型重复修正；现实与虚构同结构。

**已确认的结构前提：** 独立草地／泥地适性使用A/B/C/G四档；放弃旧存档兼容，基础重置后只维护新规则。能力修正集中查表，快照保留实际使用值；基础评语适配应与新公式一起交付。

**等待确认或实测：** 草泥A/B/C/G的0/−5/−10/−25修正建议；类型适性的+2／0／−2和+4／−1／−4幅度；Ⅱ级○是否保持−1；两种适性组合的生成概率和稀有度；各类型可达赛程数量；AI选择权重；遗传算法。真实路线具体分类需逐条人工确认，不能由国家或长短距离批量推断。

第一阶段交付标准：能在新试验世界选择一匹具有三项适性的马和一个共享赛程，清楚看到一次性能力修正，运行现有比赛，保存后重新打开仍保持一致。达到这一点再扩大内容与模式覆盖。

## 九、基础重置补充：草泥四档与练马师评语

### 草泥四档

| 档位 | 建议含义 | 建议试验修正，未定案 |
| --- | --- | ---: |
| A | 适应，正常发挥 | 0 |
| B | 可以应付，有一定折损 | −5 |
| C | 明显不适应 | −10 |
| G | 极不适应 | −25 |

此表沿用旧系统四个档位的幅度，只取消S的+5。草泥决定在某种表面能发挥多少，类型适性决定在比赛形态中的发挥，两者独立相加。G代表严重惩罚，不自动禁止报名。

例如能力80、草地A、瞬发◎，跑瞬发Ⅱ草地赛，在其他修正为零且不触发能力下限时为84；草地改为C则为74。G的惩罚远大于类型优势；符合“表面严重不合难以靠类型弥补”的目标时可接受，若希望广泛跨表面出赛则需调小。普通模式60下限会截断严重惩罚，测试中要单独观察，不能误归因于四档失效。

草泥生成建议先保证普通新马至少有一个A；A/A作为双适性组合保留，概率以后确定。这是生成建议，不是强制禁止手工创建其他组合。草泥档位与三项类型适性不要捆绑，例如不规定泥地马必须消耗◎。

surfacePref可作为生成时的抽样模板；最终真值以surfaceGrades为准。显示“草地马／泥地马／二刀流”应按两档派生或明确作为练马师判断，不能再维护一套可能与档位矛盾的独立真值。表面四档与类型三档使用不同枚举和修正表，不能因为都出现A/B就共用一张表。

### 评语需要同步改，不只是替换名词

现有comments.js中的focusSurfaces含日本草地、欧洲草地等地区目标；surfaceComment读取地区档位。post-race-comments.js的adaptationOk只检查距离、旧surfaceMod和成熟度，diagnoseLoss没有赛场类型原因。adaptation-hints.js又按地域写入认知，并将部分“无问题”诊断转成适应证据。这些必须一起调整。

建议保留既有准确／模糊／未知／误判机制和结构化claim，只改观察对象，不重做整套练马师系统：

- 表面评语只讨论草地和泥地，例如“草地适应得不错，泥地可能比较吃亏”。B的措辞为尚可、有折损，不等同于完全不适应。
- 新增独立类型评语，例如“比较适合把决胜留到后段，长时间维持高速的比赛还要再看看”。避免将其说成新增的爆发力、耐力等独立能力值。
- 练马师国籍和所属地区继续用于身份、厩舍；专业观察目标改为表面或类型，不再以“日本场擅长判断”作为适性目标。具体人物新专长暂不凭空分配。
- 赛后诊断分别识别surface_mismatch与track_type_mismatch，并携带grass/dirt或burst/sustained/attrition等稳定目标键。直接复用本场计算摘要，不重算随机条件。
- 类型判断不能仅用modifier<0：当前Ⅱ级○为−1，不应自动判为明显不合；△才是清晰的类型短板候选。◎落败也不说明该类型不适应。
- 多个不利因素并存时，明确评语可说“可能受泥地／比赛形态影响”，不能声称它必然是唯一败因；最小实现一次选一个有依据的原因，不必建立复杂归因模型。
- 认知写入采用结构化目标与判断，不通过地区中文标签解析。更新本次观察项，不因一次胜负推断其他两类适性。
- 系统内部知道判断是否准确，不代表玩家知道。玩家置信度与内部accuracy分离，保留误判玩法；不把一次胜利或一句“没问题”自动确认为全部适性优秀。

第一阶段只做基础评语生成、赛后原因和新认知目标的接通；多场证据累计、完整发现阈值、血统推断和各练马师新平衡留待以后。新增测试应覆盖：不再产生地域适性评语；草泥与类型原因不混淆；○Ⅱ的−1不被误报为△；◎落败不降档；只更新被观察的维度；玩家评语不暴露内部真假标签。

放弃兼容降低的是迁移和双轨维护成本，不会自动消除现有模式对旧字段的依赖。正式切换时仍需统一清理生成器、评语、UI、育种、CSV、剧情马、肉鸽可行路线检查和地区生成配置；测试应更新为新规则预期，而非继续要求旧模拟结果哈希不变。
